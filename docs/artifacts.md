# Artifacts

An artifact is an agent-authored fence displayed in a sandboxed browser document. An assistant reply opts in with a fenced block whose info string is exactly `html-artifact`, whose source is the page, or exactly `mermaid`, whose source is a diagram the host draws in a page of its own (*Mermaid diagrams*, below). Ordinary `html` and `svg` fences, and either info string followed by anything else, remain source. Artifacts come from committed assistant text only — not user messages, thinking, tool results, or streaming output. Their source stays in the conversation and its projected context.

## Coordinates

An artifact is addressed by its entry's seq, its text block's ordinal among the entry's text blocks, and its ordinal among that block's artifact fences, of both kinds in document order (`src/record/artifact.rs`); the fence's kind is read from the fence, not the address. Fences are found by CommonMark's rules alone — inside any container, and running to the end of their container when nothing closes them — so the web client's renderer (remark), numbering the same block, arrives at the same ordinals. `web/src/ui/artifact-fences.json` holds the cases both parsers are tested against.

## Links and serving

Nothing about an artifact is stored apart from the log entry that holds it. The entry view of a committed assistant entry (`daemon/entry_view.rs`, [control-api.md](control-api.md)) carries one link per fence, derived on every read:

- `kind` — `html` or `mermaid`, by the fence's info string.
- `url` — `/artifacts/<session>/<seq>/<text_block>/<fence>/<tag>`, root-relative, so a web client loads it from the origin it already uses, local or remote.
- `external_url` — the same path on the host's artifact-only loopback listener, for a local browser; the TUI shows it.

The tag is an HMAC-SHA256 over the session id and the coordinates, under a key the `Session` holds, random per session. Serving a document checks the tag, finds the session among the host's (or the one a session bind serves), reads the entry by seq, and extracts the fence again, so a caller cannot supply HTML. A tag is valid for its own coordinates only. A session that leaves the host takes its key with it, and its links stop resolving with nothing to clean up; a resumed session signs new ones. The links are bearer URLs: anyone holding one can read that artifact while its session is hosted.

The routes sit outside the device-token gate ([web-bind.md](web-bind.md)), admitted by exact shape (`artifacts::is_artifact_route`): a document path, its `/file` route, or a shared asset (`theme.css`, `runtime.js`, `mermaid.js`) or built-in library under `/artifacts/_efference/`. They are mounted at the web origin's root and on the loopback listener, which the host starts at its first adopt, under its own `Swansong`, and which serves no other route. The host does not name the listener: the process that serves it installs the starter (`artifacts::spawn_listener`, through `Host::set_artifact_listener`) before anything is adopted, and a host with none installed starts no listener and gives its sessions no `external_url`.

## Browser boundary

The embedding iframe uses `sandbox="allow-scripts"`, without `allow-same-origin`. Responses also carry a CSP sandbox, so opening an artifact URL in a tab of its own keeps an opaque origin. Artifact script cannot read the web client's IndexedDB bearer or browser storage. The artifact policy is separate from the web shell's: it permits inline HTML, CSS and JS, `eval` and WebAssembly, and refuses fetches and subresource loads from other origins (`default-src 'none'`, `connect-src 'none'`). Evaluation is allowed because every line in an artifact is already the agent's: code an artifact evaluates gets the same origin and policy as the rest of the page, so it reaches nothing an inline script could not. It governs the loads a document makes, not navigation of the frame itself, which the browser-boundary spike did not test (journal/2026-10-24-artifact-browser-boundary-spike.md). The artifact response permits same-origin framing; every other response keeps the shell's anti-framing headers.

The parent/runtime message channel carries sizing, theme, and one report of input: the operator scrolling up past the frame's top. A wheel or touch over the frame goes to the frame's document, so the parent's window sees only the scroll the browser chains to it, which tail-following alone would read as layout and pin back ([web-client.md](web-client.md), *Transcript ergonomics*); the runtime reports upward input that nothing in the artifact handled or scrolled, and the parent departs the tail as it would for a wheel over the window. The parent identifies a message by its source window — an opaque frame's origin is `"null"` — and no message can ask the parent to make a request or disclose its bearer. A frame's URL comes from the entry view the client already holds; the web client makes no request on an artifact's behalf.

## Runtime and presentation

The server opens every document with two harness-owned elements, right after its doctype — the stylesheet `/artifacts/_efference/theme.css`, then the runtime `/artifacts/_efference/runtime.js` — and adds `<!doctype html>` when the source has none: a fragment without one would render in quirks mode, where the root element is stretched to the frame and the frame could never shrink to its content.

The stylesheet is built into the binary from the web client's own files under `web/src/theme/`: the self-hosted fonts, then, inside `@layer efference`, the theme tokens, the element defaults, the prose rules, and the artifact baseline — transparent, edge to edge, controls in the interface font, an `<svg>` that names no fill painting in the text colour, and a full-width `.vega-embed` container, without which vega-embed's own inline-block styling draws a `width: "container"` chart at zero width. The app imports the same files, so an artifact's styling follows the transcript's when either changes, and, being layered, every rule gives way to any rule an artifact writes. The fonts load from `/fonts/` on the document's own origin. An opaque origin makes those loads CORS requests, so font responses allow any origin and the artifact policy's `font-src` admits `'self'`; the loopback listener serves the same files from the web build, except in `dev-proxy` builds, where its documents fall back to the font stacks' system faces.

The runtime puts `prose` on the root element, so the prose rules apply to the whole document. It applies the parent's theme messages — theme identity and color scheme — or, with no parent, follows the system color scheme. It reports the root element's height — the content's, collapsed margins included — and the parent bounds inline height so oversized content scrolls within the frame rather than growing the transcript without limit. The report runs from a timer, on resizes and on DOM mutations, and is posted only when the height changes: the browser runs neither animation frames nor resize observers in a frame scrolled out of view, so a frame that waited on them would keep its opening height until it scrolled into view and then resize under the operator's eyes. Measured off screen, a frame takes its height where the browser's scroll anchoring absorbs the change.

### Built-in libraries

d3, vega-embed (with Vega and Vega-Lite), Chart.js and Mermaid are embedded in the binary from `assets/artifact-libs/`, one version each, chosen from major versions models know well (`src/daemon/artifacts/libraries.rs`; the vendor README records where each build came from). The runtime defines `efference.load(name)`, which adds a script for `/artifacts/_efference/lib/<name>` and resolves to the library's global. The host serves a library's builds in dependency order as one script ending in a call that hands the runtime its global, without the builds' `sourceMappingURL` comments (the maps are not vendored, and developer tools fetching one would be refused by `connect-src`), revalidated by a hash of the script (`ETag`, `no-cache`); a name with no library gets a script that rejects the load with the names there are, and the runtime also writes that line at the top of the page, where the operator sees it. Upgrading a library changes how every artifact renders, including those in old conversations.

### Mermaid diagrams

A `mermaid` fence's document is written by the host (`artifacts::mermaid_document`): an empty container, the fence's source as a JSON string in a `<script type="application/json">` element with every `<` escaped so no source can end the element, then `/artifacts/_efference/mermaid.js` (`web/public/artifacts/mermaid.js`); the stylesheet and runtime open it as they open any artifact. The script loads the built-in Mermaid with `efference.load` and renders with the `base` theme, `securityLevel: "strict"`, and theme variables read from the stylesheet's tokens: surfaces, borders and text for nodes, edges and notes, and the data series for slices, sections and branches. Mermaid derives shades from the colours it is given and parses only hex, rgb and hsl, so each token is painted onto a one-pixel canvas over the page colour and read back as opaque sRGB. Mermaid writes those colours into the SVG rather than referring to the variables, so the script draws again when the root's `data-theme` changes, one drawing at a time. It waits for the interface font before each drawing, since Mermaid sizes boxes by measuring their labels. A source that does not parse leaves the parser's message on the page under a notice line, where the operator reads it; the agent sees nothing.

Mermaid is also an ordinary built-in library, which an `html-artifact` page may load for a diagram among content of its own. Each frame parses its own copy of the library (2.57 MB minified), which is why transcript frames load lazily (*Rendering in the transcript*).

### Files from the working directory

`efference.file(path)` adds a script for `<artifact URL>/file?path=…`, authorized by the same tag as the document. The host asks the session's permission classifier whether its own `read` of that path would run without asking (`policy::classify` returning `Clear`), and only then reads the file, as UTF-8 text up to 8 MB, from disk on every request; the script hands the text to the runtime, or a reason it was withheld, which the runtime also writes on the page. An artifact therefore sees nothing the agent could not read and inline itself. The data is not recorded: it is never projected and the agent never sees it, so it changing under an old transcript moves no cached prefix — the chart follows the file.

### Rendering in the transcript

While a reply streams, an artifact fence in its text draws as a single line — that an artifact (or a diagram) is being drawn, its line count so far, and that it renders when the reply finishes — with the source folded beneath it; the frame replaces it once the entry commits and its view carries the link. An entry with artifacts renders text block by text block, as the server numbers them. The transcript keys its Markdown components on the entry's link list and the block's ordinal rather than on the object carrying them, so re-rendering the transcript, as it does on every streamed token, leaves committed frames mounted. The web transcript shows a source view beside each frame, and a fence with no link of its number and kind stays code. Frames load lazily (`loading="lazy"`): one far from the viewport is not fetched until the transcript nears it, so a transcript opened at its tail parses no library for the diagrams above. A frame loaded off screen sizes itself there (*Runtime and presentation*), so neither tail-following nor reading upward sees it resize. The TUI keeps the code block and adds a line naming the external URL.

The guide `efference://guide/artifacts` (`assets/guide/artifacts.md`) tells an agent what an artifact gets — the sandbox, sizing, `mermaid` fences, the libraries, the stylesheet and its variables — and `src/config/guide/test.rs` checks that every variable it names is one `tokens.css` defines and that it lists exactly the built-in libraries, at their versions. The frozen session preamble names the `html-artifact` fence and points at the guide, and says a `mermaid` fence renders, and with which Mermaid version, with nothing to read first: its syntax is what an agent already writes for GitHub, and the version decides which diagram types and syntax it has. `src/config/guide/test.rs` checks the preamble names the built-in version ([context.md](context.md)).

File-backed presentation, live reload, agent-side evaluation/screenshots, external-origin permission prompts and a headless browser are separate planned work; none is required to render a fenced artifact.
