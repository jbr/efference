# Changelog

All notable changes to efference. Format follows [keep-a-changelog](https://keepachangelog.com);
one line per feature. The project is private and unreleased, so everything lives under
*Unreleased* for now. For how the system works, see [`docs/`](docs/); for the narrative
behind a change, see [`journal/`](journal/).

## [Unreleased]

### Changed
- A stream that finalizes with **nothing** (clean termination, zero content blocks, zero usage — a gateway answering for a slow upstream) is now marked retryable instead of committing as the model choosing silence, so the loop retries it rather than going idle mid-task. Marked in the assembler, so the turn loop and the fork peek both get it on the budget they already have; zero output tokens is required as corroboration so a billed-but-empty answer is left alone.
- `--upstream <slug>` pins which OpenRouter endpoint serves the model (repeatable; fallbacks disabled), distinct from the anthropic-vs-openrouter `Provider` choice one level up. Endpoints behind one slug differ in uptime and latency tail — an eval run burned its whole 12-attempt retry budget on a Vertex endpoint whose p99 sat near the client timeout while an equally-priced AI Studio endpoint was at 99.95%. Unpinned requests are byte-identical to before the field existed.
- eval: a third harness-use tier, `tcp-cache-scale` — the sealed protocol plus a `STATS` requirement the obvious data structure cannot meet, so its second pass reworks the code its first pass wrote. Exists because the sealed tier proved single-pass: four runs reached a passing suite with `edit` called zero times in three of them, leaving the editing surface unmeasured. Non-regression is structural (ordered checks, the sealed 78 shared rather than copied), and the timed check is verified in both directions.
- A fork peek whose stream dies before finalizing is **retried** on the main loop's budget and schedule (4 attempts, 1s/2s/4s) instead of withholding the result on the first abort; the withheld-result message now attributes the failure to the harness and conditions its re-issue advice on re-running being safe. Measured in a controlled run: one transient abort withheld a conformance `PASS`, the agent re-ran the suite against a still-live server whose counters the invisible run had moved, and a passing task became a spurious failure nine turns long.
- A distilled result whose kept range spans the whole content renders **without** a `@@ lines 1-N @@` header — the marker shows where curation cut, and one spanning everything states only "all of it" (82 such headers across six eval runs). Truncation is reported separately, so nothing is hidden. Adds the byte pin that was missing: no test covered a *distilled* tool result, the shape 42 of 44 results took in one measured session, so a render change to the dominant wire form used to pass every cache-prefix pin.
- `bash` no longer blocks a turn indefinitely: a foreground call still running at its deadline moves to the background on its own (`p#n`, nothing killed, no output lost) rather than parking the loop. A command that starts a server with a shell `&` leaves a grandchild holding the call's output open, so it never reaches EOF — and both recovery levers are operator-side, which an autonomous session has none of. Optional `background_after` (seconds) on the call states an expectation; `[bash] background-after` / `background-after-max` set the default and the clamp.
- TUI: thinking renders as **markdown** rather than literal dimmed lines — fences, inline code, emphasis, and lists were showing as the characters that spell them, while the web client already rendered them. Inherits the web's measurement (73.5% of 653 blocks carry an explicit markdown construct) rather than re-deriving it, and resolves the `- a\n- b` → `- a - b` regression preformatting was defending against by making the list a list. Needed a dimmed register (`DocumentNode::Dimmed`): prose dims flat, syntax-highlighted code keeps its hue separation while blending toward the register, so a code block inside thinking stays readable as code without reading as the answer.
- `unknown tool: <name>` now names the mounted tools and points a program-shaped name at `bash`, instead of stating only what failed — a hallucinated tool name previously got no useful correction from any rung on its path.
- `search` groups its matches under one path header per file instead of prefixing every printed line (matches *and* context) with the absolute path — 27–47% fewer bytes on real searches, against a measured 46% of retained bytes being repeated prefixes. Headers stay absolute so an entry pastes into the next call unchanged; a gap inside one file keeps its `--` marker. (fs-mcp)
- web: the inspector's args tab renders the call's whole input instead of claiming "no body — the header says it all", which dropped `anchor` and `content` on every edit. Multi-line values are highlighted code blocks (by the call's `language`, else its path's extension) rather than escaped JSON scalars, folded past 14 lines; scalars sort ahead of blobs.
- OpenRouter capability lookup reports `context_length` as the **max** across serving endpoints rather than the min: routing filters to endpoints that fit, so one narrow outlier no longer under-reports the window (`z-ai/glm-5.3-flash` read as 256k against a 1M model). `max_completion_tokens` stays min — it is sent as `max_tokens` and a max would pin routing to the widest endpoint.
- web: syntax highlighting runs precompiled grammars on Shiki's raw JavaScript engine — the Oniguruma-to-`RegExp` transpiler leaves the main chunk (−56 kB raw, −19 kB gzip; ~11 kB smaller gzipped overall), at an ES2024 (`RegExp` `v` flag) floor.
- TUI + web: a `read_image` call renders as a one-line header — path inline, `· long_edge N` beside it when set (image tokens scale with area) — instead of a JSON envelope, in both mirrored dispatches.
- TUI + web: a distilled result whose triage kept every line (a third of measured results) presents like any whole result — no `distilled · kept n of n lines` head; partial distillates keep their count. The web `ResultRender.rawDiffers` field, dead since the per-result raw expander moved to the inspector, is removed for `stateWord`.

### Fixed
- A `write` fs-mcp refuses now preserves the body and returns a retry token; sending that token back as `contents` with the flag the refusal asked for writes the same text, so a confirmation stops costing a regenerate. Measured across two `.efference` corpora: 9 rejections in 5 sessions, ~40 KB of discarded bodies, only 4 of 9 retries identical — the worst case took three full bodies for one write, the middle pass silently dropping a third of the file. Covers both refusals that dropped a body. (fs-mcp)
- `write` replaces an existing file through a temp file and a rename instead of truncating it in place, so a concurrent reader sees the old bytes or the new bytes and never the empty-then-partial middle; the original's permissions are carried across, since rename replaces the inode. `append` and exclusive-create are deliberately unchanged — the first would become O(file), the second's single open is the existence check the already-exists refusal depends on. (fs-mcp)
- The usage topic's context-window occupancy tracks main-loop turns only. A fork peek, an idle triage, or a spotter assessment carries its own much smaller prefix, and folding those into the readout made reported context *drop* mid-turn and correct itself afterwards (observed live 2026-08-23, ~27k → 6.8k; the regression test reproduces 27010 → 6808). Side-channel usage still counts toward the cumulative totals and cost.
- `list` accepts brace globs (`{assets,docs}/**/*.{png,jpg}`), which used to be read as a literal directory and answered "Path is not a directory" — and, in the same function, a glob no longer prunes the directories it needs to descend: `src/**/*.rs` returned 28 of 246 files, silently, as a listing that looked complete. (fs-mcp)
- web: a straggling output delta that arrives after the entry it describes has committed no longer opens a fresh live block — the daemon gives `log` strict priority over `output`, so the commit can overtake queued deltas, which left a nameless call block holding a trailing `}` (or the message's last sentence rendered twice) until the next entry committed.
- web: the tasks pane seeds its tail from `GET /processes/:id/output`, so a process already running when the client connects renders its output instead of an empty `<pre>`; bytes dropped at the retention cap are reported above the tail rather than silently skipped.
- web: a call head wraps onto continuation lines instead of shrinking its path to a one-character-per-line column beside squeezed basename links — one `read` naming four files ran 2673px tall on a phone, now 342px.
- web: a distiller note (and markdown prose) no longer has its line-ends cut at the screen edge on a narrow viewport — as a flex item the note's `min-width: auto` floored it at the longest identifier it contained, so the box grew past its row.
- web: the composer drops the "rides along with the pending result" hint; the "your turn" indicator already says whose turn it is, and riding along is just what sending out of turn does.
- The loop-owned tools (`consolidate`, `list_processes`, `read_process`, `kill_process`, `check_inbox`) now carry spotter briefs with behavior annotations — they joined `tools[]` outside the toolbox with no brief path, so the spotter judged them as bare names and called them opaque; `agent::brief` mirrors `agent::tool_definitions`, and a harness-owned tool's hints render without the self-reported caveat.
- The spotter's scope block renders path grants resolved to their absolute form (configured spelling kept as an annotation) and states that a move's relative paths resolve against the cwd, with a worked example — a spotter had gated a plain in-cwd write by comparing spellings (`scratch/…` "not under `.`") instead of resolving; replaying the observed false gate 10× post-fix cleared every time with resolution-aware reasons.
- A `keep` range wholly outside the shown line numbers (a peek adopting `grep -n`'s embedded coordinates, or a 0 start) is rejected at parse time and retried in-fork with a nudge naming the actual bound, instead of being silently dropped at render into a note-only projection; overshoot from an in-bounds start still clamps.
- The fork's `retain`/`triage` verdicts accept stringified notification ids (`"pin": ["102"]`) — the peek reads ids out of rendered prose, so models transcribe them as strings; a live fork answer whose only defect was quoting cost a full retry.
- An upstream stream that dies before finalizing (silent close, in-stream error, mid-stream transport failure) no longer commits as a clean turn: the partial is appended as a record-only entry carrying the failure (excluded from projection, so the bounded retry — 4 attempts, doubling pause — rides the cached prefix), exhaustion and pre-stream request failures post a turn-not-completed notification, and the error body lands durably in the log instead of stderr alone; the fork peek fails the gate and the spotter fails closed on the same detection.
- The per-turn output budget follows the model's reported cap (`max_output_tokens` from the boot lookup) instead of a hardcoded 4096, which a reasoning model's thinking exhausted before any text arrived; a cap-terminated turn now commits what arrived and posts a notification instead of silently going idle.
- Keepalive carries a read-only tripwire: a `max_tokens: 0` ping that reports generated output tokens (mandatory-reasoning endpoints think on pings, ~4k tokens each) ends the keepalive for the session.
- Foreign models think: the `thinking` field is omitted rather than sent as `disabled` for non-Claude models (mandatory-reasoning endpoints rejected the explicit disable, and no OpenRouter model ever produced thinking blocks), with adaptive granted on auto turns when every serving endpoint lists `reasoning` in the boot capability lookup.

### Added
- `eval/harness/`: a reproducible non-interactive harness-use exercise — playbook (run/observer protocol, pinning rules, metric definitions) plus a first task (`tcp-cache`: bespoke TCP protocol spec, 53-check exact-byte conformance suite verified against a reference implementation).
- A byte pin over the **whole request envelope** (`request_envelope_matches_expected_wire_bytes`), not just the projected `messages`: the provider matches the entire body, and a tools-array mutation once moved the cache prefix without failing either projection pin. It caught `tool_choice`'s `disable_parallel_tool_use` on the way in.
- tui: a tool result's images render in the transcript through the terminal's graphics protocol (kitty / iTerm2 / sixel via `ratatui-image`, halfblocks anywhere else), with `--images` / `EFFERENCE_IMAGES` overriding detection; the reserved rectangle is metadata-sized (no reflow when bytes arrive), a partially scrolled image paints as a row-sliced halfblock mosaic, and live entries fetch bytes by reference over the control socket.
- web: a tool result's images render in the transcript — plain `<img>` elements against the image route (browser-native fetch, caching, and lazy loading), sized by the view's width/height so layout never reflows.
- Logged images are a resource: control-channel entry views omit a result image's base64 `data` (keeping `media_type`/`width`/`height` for layout), and `GET /v1/log/:seq/images/:idx` serves the decoded bytes under the stored media type, immutably cacheable — so an image never rides a log window, a replay, or the SSE stream.
- MCP image results: an image content block in a tool result (embedded or connected server) is realized into a wire image block — sized through the `read_image` engine at its default long edge, header line reporting realized size and visual-token cost — instead of a `[image … not rendered]` placeholder; an undecodable block degrades to a placeholder naming the failure.
- Provider-conditional image placement: projection takes an `ImagePlacement` fixed at boot — Anthropic keeps images inside `tool_result` (the documented shape); OpenRouter emits the portable form (text-only `tool_result`, image as a following user-block) since its skin documents tool-output images nowhere.
- `read_image`: pull an on-disk image into context as a real `tool_result` image block, at a model-chosen resolution (`long_edge`, default 1568 / max 2576) — sized by the provider's own token-budget rule, JPEG-stays-JPEG / else lossless-WebP encoding with verbatim passthrough when nothing changes, realized size + visual-token cost in the result header, bytes stored inline in the log as base64 and gated by the same read-path grants as `read`.
- `efference spotter-eval`: run the labeled spotter corpus (`eval/spotter/`) against a model through the production `assess` path — per-class scoring (human-miss vs false-gate), per-case flip rate across repeated runs, latency percentiles, token totals, provider-billed cost per generation id on OpenRouter, and a `--persona` override so persona edits measure against a fixed baseline instead of ad-hoc replays.
- web: quiet chrome on narrow — at rest the dock is one status row (`⋯` reveals the dials and tab strip; interrupt, a held pace, and counted tabs always show through), and the dev scrub badge moves to the top-left.
- web: the phone breakpoint — an interim usability pass at 700px (label gutter stacks above content, every tool's result and call body truncates to a glance with the whole behind tap-to-inspect, the inspector becomes a full-width sheet, the composer band collapses behind a floating `✎ compose` chip and sends by button, gate decision rows wrap), plus two both-form-factor affordances: a jump-to-latest chip and history-backed overlays (back/edge-swipe dismisses the sheet); fixes the phone-width composer collapse (WebKit `field-sizing` × indefinite flex basis × a nowrap hint).
- TUI: the sidebar takes focus — `Tab` in command mode toggles onto the right-docked column, `↑/↓` walk its actionable rows (processes, pending proposals), and each row carries verbs (`kill`; `commit`/`cancel` on a proposal) dispatched by row identity so a vanished row can only ever no-op. Proposal commit/cancel now works from the terminal.
- File change streams: `GET /files/<path>` with `Accept: text/event-stream` serves change pokes for that file over a core fs watcher (`src/fswatch.rs` — one notify debouncer, consumers on a broadcast channel, refcounted parent-directory watches); the viewer's 2 s poll replaced by an `EventSource` whose every poke and reopen answers with the same conditional GET.
- web: the file viewer — an overlay filling the band between the top bar and the dock, so the composer and a pending gate stay at hand (the gate float shows while the viewer covers the in-flow surface) — opened from `open ⤢` on any call naming a within-cwd file, and in the inspector footer, showing the file as it is on disk over `/files`: absolute-numbered highlighted source, markdown rendered with a source toggle, changes-since-you-last-looked highlights from diffing successive fetches (line tint in source, block tint in markdown), freshness from log-frame refetch plus the change stream, and follow-the-agent across files with a toggle that keeps live reload while suppressing the jumps.

### Fixed
- The gate no longer dumps the pending call as escaped JSON — a `write`'s file body rendered as one `\n`-escaped line on the surface where a human commits. The call and its verdict render once, in the transcript above the affordance.
- Every terminal `/v1` handler halts its conn: trillium's router doesn't halt on match, and the TCP bind mounts the frontend handler after the router — under `dev-proxy` it forwarded answered-but-unhalted conns to Vite, 502ing every plain JSON route.
- The web client's connection survives React StrictMode's mount → cleanup → remount (dev builds only): the connector is owned by the effect and rebuilt on remount, instead of being permanently closed by the simulated unmount.
- The TCP gate now reads every `cookie` header field line (via trillium-cookies): browsers split one line per cookie over h2/h3, so any unrelated cookie on the daemon's host locked browsers out of cookie auth while curl (one line) passed.
- `efference serve --bind <addr:port>` adds a TLS-terminating TCP listener beside the Unix socket — the same `/v1` API behind a hardening + auth gate (Host allowlist, Origin/Content-Type checks, cookie or bearer), with all credentials HKDF-derived from one injected `EFFERENCE_ROOT_SECRET`, a TOTP bootstrap (burned codes, rate-limited with lockout) served from an anonymous page at `/`, and `efference open` (`--qr`, `--bearer`) minting fragment-token links and authenticator enrollment over the UDS. The bind flag family reads `EFFERENCE_BIND`/`EFFERENCE_HOST`/`EFFERENCE_TLS_CERT`/`EFFERENCE_TLS_KEY` as defaults; `--bind ""` overrides back to UDS-only. A TLS bind also serves HTTP/3 (QUIC on the same port, advertised via alt-svc).
- Every tool call carries a required `intent` — one line on why the call is being made, injected into every mounted tool's schema and stripped before dispatch. It leads the call entry in the TUI and heads the result block the fork peek triages, so the verdict's `note` answers it. The spotter does not see it.
- Connected HTTP providers authorize over the MCP OAuth flow: a `401` at boot runs discovery (RFC 9728 protected-resource and RFC 8414/OIDC authorization-server metadata, both probe ladders), obtains a `client_id` by Client ID Metadata Document or dynamic registration, and completes an authorization-code + PKCE dance through a fixed-port loopback redirect, with `iss`/`state` validation and RFC 8707 resource binding. Tokens persist between runs; `--reauth <server>` re-runs it.
- A declared MCP server that does not mount now fails `efference serve` instead of being skipped with a warning; `optional = true` on the stanza opts out, and an optional server that fails is reported both to the operator at every launch and to the model as a preamble section naming it and the reason.
- `efference spotter --tool <name> --input <json>` judges a structured move, mounting the servers `--config` declares so the verdict is made against the real tool definition; `--show-move` prints the exact block sent and `--no-brief` withholds the brief for an A/B.
- The spotter judging a structured call is shown a brief for its tool first — the server that advertised it, its description, its input schema, and the server's self-reported behavior hints (`readOnlyHint` and friends, labelled as claims) — instead of a bare name and a JSON blob.
- A namespaced tool name reads dotted on every human-facing surface — transcript, sidebar policy labels, and the config file the write-back produces (`ferritin.get` for the wire's `ferritin__get`); `tools` grants accept either spelling and resolve to the wire name at validate.
- Connected providers speak the stateless `2026-07-28` revision: mounting probes `server/discover` and falls back to the `initialize` handshake, and every request carries the client `_meta` that revision requires.

- A tool call's arguments render as arguments *while they arrive*: the input is parsed as a JSON prefix, settled arguments render through the same per-tool renderer a committed call uses, and the one value still in flight renders as content — so a `write` shows `write src/api.rs` with the file's contents accumulating in a syntax-highlighted block. Only a value whose closing quote has arrived can back an identity claim; before any pair closes, the raw bytes are shown as before.
- A code block that is still being appended to is highlighted incrementally, continuing from the syntect state saved after its last complete line, so a streaming write colours the lines that arrived rather than every line it holds (401 lines per frame at 400 lines, now 1).
- `--frame-cost` (on `tui` and `gallery`) times each paint: p50/p95/max over a rolling window plus the last walk's laid-out and highlighted node counts in the status bar, and the session's distribution — including how many frames ran over the 30ms tick — on exit.
- `efference gallery --stream` plays a scripted live tool call over the offline gallery (`--chunk`/`--interval` set the pace), so the render behaviours that only exist at animation rate can be driven without a daemon.

- Streamed thinking persists in the transcript as a dimmed block instead of vanishing when the model starts acting. It was a generation *phase* — one slot — so `tool_call_start` replaced it, and a turn that thought briefly before calling a tool showed its reasoning for a few frames and then lost it until the turn committed. The live and committed blocks are built by the same renderer, so the handoff is invisible.

### Fixed
- A distilled tool result shows the **triaged** lines in the TUI for every tool, including `read` and the edit tools, which used to render their full output. The tool-specific parse now emits rows carrying their raw line number, so the kept-line filter applies after it: a triaged `read` keeps its highlighting and framing-stripping, a triaged edit keeps its colored diff. A large file read distilled to a few lines was showing in full, hiding the difference between the operator's view and the agent's.
- Committed thinking keeps the line structure the model emitted. It was reflowed to paragraphs — single newlines became spaces, so a list read as one run-on line — to work around an entry double-spacing one node per line. It also means the block no longer changes shape when the turn commits, since the live thinking phase already rendered line by line.
- Scrolling up during a stream stays where it was put. A re-projection drops the layout cache, and the event loop re-projects before draining an input burst, so a scroll arriving mid-stream saw no layout — and `max_scroll` answering 0 there made every scroll read as "at the bottom", re-arming stream-following and snapping the viewport to the end from wherever was being read.
- Wrapping a long line is linear in its length rather than quadratic: the wrap policy measured the whole remaining text once per row emitted, purely to test whether it fit. One 16k-column line (a tool call's JSON input mid-stream, a minified file) cost ~300ms per wrap in release, repeated every frame while it streamed.
- The live tail no longer renders a blank row between every line: an entry separates its child *blocks* by a blank row, and streaming tool output, thinking, an arriving tool input, and a pending user turn each modelled one source line as one block.
- Streamable-HTTP requests carry the `Mcp-Method` and `Mcp-Name` headers `2026-07-28` requires, with the spec's base64 sentinel encoding for values that cannot ride raw. Their absence was invisible against mcplease-backed servers, which do not validate them, and rejected by Sentry with `HeaderMismatch`.
- An MCP server name may no longer contain `__`; the separator inside a name would move the namespace boundary that the wire→display and dotted-config→wire mappings both resolve as the first occurrence.
- Tracks the published mcplease 0.3 API (`Dispatch::call` with a `RequestContext`); embedded tool results now fold through the same `CallToolResult` renderer as connected ones, and an interim (`input_required`) result from a connected server lands as a named error instead of an empty success.
- Composer movement, deletion, visual-row wrapping, and caret measurement use extended grapheme clusters, so combining characters and emoji sequences are not split by editing or layout.
- Token usage merges `message_start` and `message_delta` per field, so OpenRouter turns report real input and cache read/write counts instead of the all-zero `message_start` placeholder.
- The fork peek's ask is scoped to the results of the gate it opened, and a single-result gate asks for a bare `keep`/`note` with no call id; an unbounded ask had models re-triaging the whole transcript against prior results' `[seq]` tags, failing coverage and withholding output.
- A coverage rejection records which ids the verdict *did* answer, so a scoping failure is distinguishable from an empty verdict in the log.
- The fork peek sends the agent turn's exact request envelope (shared tools array, `tool_choice: auto`, same thinking policy), so peeks read the agent lineage's prompt cache instead of re-writing the transcript cold on every gate.
- The trailing cache breakpoint marks the last *text* block — a marker on a `tool_use`/`tool_result` block bills an unreadable cache write on OpenAI-fronted endpoints.
- Transient upstream 429/5xx responses retry with a bounded backoff, and an exhausted completion now returns the session to idle instead of terminating the daemon.

Only verbs that apply are shown: `background`/`kill` are foreground-`bash`-only (the handoff adopts a live child; `kill` races an abort future no other backend awaits — the `interrupt` entry below since made the interruption half universal), `pace` is reachable in every state rather than only while held, and `held` is a modifier that renames the hold verb to `resume` wherever it appears. Which tool is running is read off the committed log — the last call with no paired result — so no daemon round-trip was needed. Replaces the fixed per-state-family sets and the right-pinned `detach` universal.
- `interrupt` — `POST /interrupt` now **latches** (`AtomicBool` consumed at the junctures either side of a call), so it reaches tools nothing can suspend: the loop stops and the in-flight call's output is withheld from the model, kept in the log with `wire: Elided` (its first construction site) and never sent through the redaction fork. Taken before a call runs it stops the turn instead. The strip carries it in every active state — labelled `kill` on a foreground bash, where it also kills the process group — replacing the state that offered no interruption verb at all.
- Per-session scratch dir: `serve` mints a private `$TMPDIR` (mkdtemp-style, mode 0700), exports it to every bash child (foreground and background), always grants it rw, and cleans it up on session end (`--keep-scratch` retains it). Structured tool paths expand `$TMPDIR`/`${TMPDIR}` at one choke point upstream of classify/spot/exec (frozen boot-time map, allowlist starts at exactly `{TMPDIR}`, unlisted names hard-error — never expand-to-empty); the spotter's scope block aliases `$TMPDIR` to the granted path so bash scratch writes are judgeable.

### Changed
- The session's config file is no longer named up front in the preamble — that high-salience "here's what you're allowed to do" pointer drew sessions into reading and probing their own perimeter as a first move. The perimeter stays out of attention; the gate-rejection message names the config as the request channel only when a move actually strays.
- Orientation is config, not code: the hardcoded environment block (cwd/platform/project-type, `env::orientation` + marker detection) is deleted; *where the session is* is now an ordinary `[context]` exec entry — the config-less scaffold ships `"Environment at boot" = { exec = … }`, and a written config owns the whole preamble.
- Model selection moved to a per-session `serve --model <id>` flag (default `claude-haiku-4-5` for dev).
- Tool definitions unified into one source shared by the loop, the keepalive ping, and the dev `wire` view (closing a cache-correctness gap).
- The distilled-note prefix changed from an em-dash (`— `) to the `⟢` provenance sigil already used by surfaced-context lines, so a surviving triage note is honestly signed as harness-curated output without invoking mechanism vocabulary. Render-layer only; the fork's `note` schema is unchanged.

### Fixed
- Fast-path permission grants no longer misfire on two dogfood-caught cases: a trailing fd-dup redirection (`cmd 2>&1`) stays on the bash fast path (only *file* redirections gate now), and a batched `read` spanning both `[paths]` and `[context]` grants clears per-path across the union instead of gating.
- Guard against runaway tool results overflowing the request (400 on oversized content).
- Streamed control characters, a turn-loop livelock, and a resume edge case.
- Extended thinking, end to end: the assembler folds streamed `thinking`/`redacted_thinking` blocks (signatures preserved) into leading assistant content, `project` renders them first on the wire, and the request's `thinking` field rides on `tool_choice` (main turn `auto` → adaptive+summarized; the fork's forced choice and the keepalive → disabled, the one illegal pairing made unrepresentable). Replaces the earlier thinking-disabled stopgap; thinking blocks are stored verbatim, not yet elided.
- A config edit that no longer parses fails loud, not silent: reload keeps last-good policy (fail-closed) and raises a `config-parse-error` notification naming the error, so the session learns its edit didn't take instead of thrashing. Schema-teaching headers on `efference.toml` + the config scaffold lead with the `scope`-is-a-string anti-footgun.
- Thinking is kept, not just streamed past: a committed turn's extended thinking renders as a collapsible block at the head of the turn (opening paragraphs always visible, expand for the rest, keyed by `seq` so the toggle survives re-projection) — reasoning streams too fast to read live, so the transcript holds the copy a human actually reads.
- A turn that produces no prose is visibly working: the streaming sink is typed (`Streamed` — text / thinking / tool-call-open / tool-input), so thinking and a tool call's arriving arguments reach clients as their own `/stream` events instead of not at all, and the TUI renders the live phase in full — the thinking so far, or `❯ calling <tool>…` over its JSON input as it accumulates — superseded by prose, by the next phase, and by the committed turn. The serve log prints `(generating — turn N)` before blocking on the model, so its last line is no longer a stale `idle` that reads as finished.
- Every committed grant is written to the session's config file, so that file is a complete record of the perimeter the session ran under — the artifact an operator reads and copies grants up from. `Lifetime` (`session`/`persist`) is retired: it had been drained of meaning by per-session config dirs, and every live caller hardcoded `session`, so the write-back had never run outside tests. A failed write now fails the grant rather than silently degrading it to session-only.
- A config edit is now adopted or reverted, never approved-but-inert: the session's config file is held in memory as a format-preserving TOML document under the invariant that the disk always holds the last content that parsed, so a write that doesn't parse is undone (comments and key order intact) and comes back to its author as an error naming the parse failure — the same rule for a gated tool write and an operator's hand-edit alike.
- A gate is always visible, whatever the call's length: its spotter reason, affordance, and `⏸` marker render as siblings of the exchange rather than inside its collapsible body, where a command more than a few lines long had been clipping the whole gate off screen. Structured annotations *about* a call now sit beside the exchange; the collapsible body holds only agent-generated content.
- The spotter's verdict renders beside every call it judged, stance first (`spotter cleared · …` / `watching` / `gated`), in the dim register — cleared calls included, which are most of them and previously had no surface at all, and resolved gates, where the verdict is the only record that a human overrode the spotter.
