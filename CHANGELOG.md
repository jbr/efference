# Changelog

All notable changes to efference. Format follows [keep-a-changelog](https://keepachangelog.com);
one line per feature. The project is private and unreleased, so everything lives under
*Unreleased* for now. For how the system works, see [`docs/`](docs/); for the narrative
behind a change, see [`journal/`](journal/).

## [Unreleased]

### Added
- **`efference setup` logs in to ChatGPT** (docs/operating.md): the subscription is one provider row with two ways to hold it — piggyback on Codex's cached login, or log in here, which opens the browser, keeps the grant as `oauth:<connection>`, and needs no Codex install. A way that is closed says why (no Codex cache to read, no store to write) instead of being hidden, and an `oauth` connection is re-authorized in place from the management flow.
- **`auth = { kind = "oauth" }`: efference's own ChatGPT login** (docs/transport.md): the grant is obtained, stored in the secret store under `oauth:<connection>`, and refreshed against the issuer from the token's own `exp` — no Codex install, and unattended renewal. Separate from Codex's grant, since a refresh can rotate the token its `auth.json` holds.
- **`efference setup` manages the connections already configured** (docs/operating.md): with a config file it opens on the connections in it — each with a locally-read readiness note — and offers edit, rename, disable (`disabled = true`), and delete, keeping the add flow for a machine with no config. Moving a key into the store needs no paste and refuses a `scheme://` reference; moving one out reveals it and leaves the stored copy unless separately cleared; a rename moves `inference:<name>` write-then-verify-then-delete. A connection setup cannot read whole is an error naming it rather than a row omitted.
- **GPT-5.3 Codex Spark support** (docs/transport.md): the subscription provider accepts its text-only capability profile, and `usage.plan` preserves separately metered quota families and the active exhausted limit.
- **A child's status wakes its creator** (docs/tools.md): `create` from a session subscribes the caller, and each of the child's decision points — a gate, a turn completing into idle, a stall, its end — lands in the caller's inbox on slot `session:<id>` as a must-wake notification the loop pins whatever the triage peek decides (docs/inbox.md). `sessions__subscribe`/`sessions__unsubscribe` hear any session in the project without the wake; `wait` counts a subscription as a wake source. Children end with their creator unless created `detached`.

### Changed
- **A child's identity line names the session that created it** (docs/context.md): when the host recorded a `created_by`, the system prompt adds "It was created by {id}, which you can reach the same way.", so a delegated session has its creator's return address instead of hand-carrying one through the task text. Absent for a root; the id is the host's record, not prompt text, and carries no liveness or authority claim.
- **The identity line names the session's id beside the model** (docs/context.md): the system prompt opens "You are {model}. This session is {id} on this host; that is the id other agents use to reach you.", so a session can hand another agent its own address without inventing one or carrying it through prose.
- **A host refuses to start when a configured connection cannot authenticate** (docs/operating.md): it names each connection and its reason instead of starting and failing every session that touches that provider. `disabled = true` keeps a provider written down without blocking a launch.
- **The idle triage runs on the agent's own lineage** (docs/redaction-fork.md): with a separate `--triage-model`, only the per-result peeks go to it; the wake decision an idle session makes on a notification sends the agent's client, tools, and thinking, reading the cache the keepalive holds warm.

### Fixed
- **A rejected creation reserved the name it failed on** (docs/control-channel.md): the session dir was minted before the effort level was validated, so a bad `--effort` left the dir behind and the corrected retry collided with it. The effort check now runs before the mint, and any later preparation failure rolls back what that attempt minted — its session dir and scratch. A refused mint owns nothing and removes nothing, so a collision with an existing or racing session leaves its files untouched.
- **Session teardown resolved before its background children were gone** (docs/supervisor.md): teardown sent SIGKILL and continued, but a killed process stays in the table until it is waited — so scratch removal could race a child still writing under it, and `shut_down().await` could resolve with the processes still alive. Teardown now waits for the reap each `drain_background` already performs.
- **A host outliving its credential could not recover** (docs/transport.md): an expired Codex token 401'd every session for the host's life, because the token was copied into each endpoint at launch and `codex login` could not reach it. A `token_expired` rejection now re-reads the credential from its source and retries, repairing every session at once; `env` credentials, frozen in the host's environment, report that they have no source to re-read.
- **A trajectory started by a notification wake read as idle**: the idle-triage escalation never set `running`, so `/settle` returned at once, the status watcher reported idle, and a turn submitted meanwhile sat in `queued` with nothing to explain the wait. Escalation now marks the loop running until it parks (docs/inbox.md).
- **A connection that never opened panicked the session loop**: `sse_open_failure` read a response body from a transport that did not exist. A refused connect now records a completion failure and stalls, as other request failures do.
- **Resolving a gate pings state**, so the `gate` topic clears when the decision lands rather than at the loop's next append.
- **A user-wide host** (docs/control-channel.md): `efference host` binds `~/.efference/host.sock` and serves every project; clients look for a host at `.efference/host.sock` here, then there. `GET /sessions` carries each session's `cwd`, and every client resolution — the TUI, the `control` verbs, `efference mcp` — keeps to sessions whose cwd is the current directory, so a plain `tui` in one project never lands on another's session. `tui --new` creates on the first live host; `--host-socket` overrides.
- **The agent loop runs on the host runtime** (docs/control-channel.md): the loop is `Send` end to end — embedded MCP state behind a `Mutex`, `Frontend`/`Spotter` futures bounded `Send` — and is spawned on the host's multi-thread runtime instead of a thread with a current-thread runtime of its own. Fixes an in-session `sessions__create` hanging its caller forever: the blocked loop stopped driving a pooled h2 connection the host-side boot then borrowed. In-session `create`/`end` wait through `block_in_place`.
- **A session creates only inside its own project** (docs/tools.md): `sessions__create` refuses a `cwd` whose `.efference/` base is not the caller's, before anything is minted; a child made elsewhere was unreachable by every later verb.
- **`sessions__approve` is classified as the action it authorizes** (docs/permissions.md): before the parent's permission cascade runs, the host resolves the child's held call, following an approve-of-an-approve to its leaf, and the parent's fast path, spotter, and human gate judge that leaf under the parent's config; a granted `sessions__approve` clears blind as documented trust. `GET /state`'s `gate` and the TUI show the child's command under the parent's call, and a moved gate refuses before classification.
- **The control tools mount inside a session** (docs/tools.md, docs/operating.md): a hosted session's toolbox carries `sessions__<verb>` backed by an in-process `Host` executor that knows the caller. Self is never a target; mutating verbs reach only sessions the caller created (`created_by`, host control state, shown on `GET /sessions`); `notify` and the reads reach the caller's project, and other projects are not found. A `turn` from a session is attributed `session[<id>]`; `create` from a session uses the caller's cwd and child environment. `settle` and the `wait` flags are not available in-session.
- **`wait`** (docs/supervisor.md): a loop-owned tool that blocks until the inbox has a notification of any origin and returns the pending bodies, refusing immediately when nothing can wake the session; an operator interrupt still cancels it. Replaces the `read_process` poll loop a session falls into when it will not end its turn before its assignment is done.
- **Control tools live in the library** (docs/operating.md): the mcplease `Tools` enum behind `efference control` and `efference mcp` moves from the binary to `src/control_tools.rs` behind an `Executor` seam whose one variant today is the HTTP `Client`; the binary keeps only the two mounts. Groundwork for mounting the same verbs inside a session (backlog/multiagent/sessions-surface.md).
- **Turn provenance** (docs/control-api.md, docs/log-and-projection.md): `POST /turns` takes an optional client-asserted `source` (`web`, `mcp[<name>]`, `agent[<id>]`), recorded on the `User` entry and rendered as a `source:` prefix line on its wire block so the model can tell voices apart; absent — the operator — renders no prefix and leaves every existing log byte-identical. `efference mcp` fills it from the caller's `clientInfo.name`, `turn` takes `--source`, the web client sends `web`, the TUI sends nothing, the transcript and TUI show it, and the preamble states the convention.
- **`transcript` and `entries` replace the `log` control verb** (docs/operating.md): `GET /transcript` renders a log window at reading grain — prose whole, calls by name and intent, results by size and verdict, no bodies — and `entries <seq>…` fetches whole entries behind its lines. The raw window verb is gone: over MCP a 30-call turn came back as 56 KB the mounting harness refused to inline, and at a terminal the jsonl is the same bytes.
- **`efference mcp` mounts against the host** (docs/operating.md): the MCP server no longer resolves a session at startup — it addresses `.efference/host.sock` (or `--host-socket`), every session tool takes a `session` id, and three host tools land beside them: `sessions` (list with titles), `create` (a session in a working directory, the mount's environment as its base), `end` (teardown). `efference control` gains the same three verbs; `Client::sessions`/`end_session` reach the host routes.
- **Session ids are word pairs, and sessions have titles** (docs/session-title.md): an unnamed session is minted `adjective-noun` (`amber-heron`), free on the host and on disk, never renamed; after each trajectory that answered a user turn the triage model is asked, off the cached prefix and as plain text, for a one-line title, recorded as a `Title` log entry that projects to nothing. `session_identity` carries `id` and `title`, `GET /sessions` lists titles, `PUT /title` / `efference control title` set one by hand, and the TUI sidebar, web top bar, and session list show it.
- **The secret store** (docs/secrets.md): `src/secrets.rs` keeps named strings in the OS credential store — the login keychain in-process when the binary is identity-signed, through `security(1)` when it is ad-hoc (every `cargo build`), Secret Service on Linux. `auth = { kind = "keychain" }` reads a connection's key from it; `efference setup`'s "paste it now" choice writes one; MCP OAuth grants move there from the per-project `mcp-auth.json`, which is gone.
- **The root is minted, not supplied** (docs/web-bind.md): the web bind's root secret is 32 random bytes kept in the secret store, minted on the first `host --bind` and read after; `efference auth rotate` deletes it, which signs out every browser, invalidates the authenticator enrollment, and drops push subscriptions. `EFFERENCE_ROOT_SECRET` and its spawn-site strips are gone.
- **`efference setup`** (docs/operating.md): the first-run path, which a bare `efference` runs when `~/.efference/config.toml` is missing — inline terminal prompts for provider, connection name, credential source (an environment variable, or Codex CLI's cached login; the OS keychain is listed and refused until the binary is signed), agent and spotter models, with live key and model checks where a key is on hand, and a file written `0600` that keeps an existing file's entries and comments.
- **Host-owned inference connections** (docs/transport.md, docs/operating.md): `efference host` loads named provider connections from `~/.efference/config.toml` (required) and their credentials from its own startup environment (`env` key or the Codex cache), once; a session selects `<connection>/<native model>` per role — main, spotter, and an own-client triage that must share the main dialect — with `[defaults]` filling omissions. Host secrets are masked by name in every session that holds them and never enter a child environment; `session_identity.inference` reports each role's connection, and the TUI sidebar and web top bar show it.

- **Interrupt ends a generation in flight** (docs/control-channel.md): `POST /loop/interrupt` — the TUI's second `Esc`, `efference control interrupt`, the MCP tool — now also ends a model read that is streaming or hung: the stream is dropped, what streamed is kept as a record-only entry marked `Aborted` (counted against no retry budget), and the loop returns to idle where a queued turn lands at once. An interrupted own-model peek withholds its verdict.
- **`--name` reaches hosted sessions** (docs/control-channel.md): `tui`, `control`, and `mcp` resolve a name to its own socket or to `/sessions/<id>` on the host, and discovery counts hosted sessions; a name nothing serves is an error, and the TUI connects before taking the terminal instead of opening an empty screen.

### Fixed
- **`efference host --socket <path>` binds there**: the global `--socket` was parsed and ignored by `host`, which always bound the default; an explicit path is now honored and its directory created.
- **OpenRouter's default spotter is a slug**: with no `[defaults].spotter`, an OpenRouter main connection now defaults the spotter to `anthropic/claude-haiku-4-5`; the bare id failed the metadata query at boot.

### Removed
- **`efference serve`** and provider selection from the environment: `EFFERENCE_PROVIDER`, `EFFERENCE_API_KEY`, `EFFERENCE_CHATGPT_ACCOUNT_ID`, the `ANTHROPIC_API_KEY` fallback, and the unconditional masking of those names. A host is the only way to boot a session; the dev verbs that dial a provider (`dev wire`, `dev peek`, `dev spotter`, `dev spotter-eval`) resolve `--model` through the same config.
- **`efference tui --new`** (docs/operating.md, docs/control-api.md): create a session on a running host — this directory as its root, this shell's environment as its base, `--name` as its id, `serve`'s session flags — and attach under `/sessions/<id>/`; quitting detaches. The control client takes a path prefix (`Client::at`) that joins `/v1` routes only, and `CreateSession` is the one body type both ends share.
- **`efference host`** (docs/control-channel.md, docs/control-api.md): one process hosting many sessions as their control endpoint — `GET /sessions`, `POST /sessions` on the Unix socket (the body carries the session's cwd and environment), `DELETE /sessions/:id`, and each session's own API under `/sessions/<id>/`, routed in-process into the same handlers a session bind serves.
- **`dev cache` states uncached input tokens beside the warm rate** (docs/log-and-projection.md): the rate counts any nonzero read as warm, so a session of preamble-only hits reads as healthy; the token column is what makes 81% warm against 2.07M uncached input legible.
- **`Config::from_toml`** (docs/permissions.md): parse a config from text through the same decode-and-validate path a file takes; every test that uses a config as an input now writes it as TOML.
- **`Distilled` is a struct** (docs/log-and-projection.md): `WireState::Distilled(Distilled)` carries the verdict as one value with builders on it, and `render_distilled` takes it, so a field added to the verdict is one setter and one render clause; wire bytes are unchanged.
- **`intent` is the question, `note` the answer, and triage can ask for a better question** (docs/tools.md, docs/redaction-fork.md): the preamble states that a reader between the agent and the tool keeps what answers the intent, asks for the why when the what is obvious, and says a write's intent is only the why; the `note` ask prefers "it didn't" over summarizing around a miss; a new optional `intent_feedback` on `retain`, scoped to the intent and never the task, reaches the wire and the TUI as `⟢ re your intent: …`.
- **Codex SSE without a `content-type` recovers on the published trillium-client 0.9.19** (docs/transport.md): the Responses dialect rebuilds the event stream from the refused negotiation instead of a local dependency patch; other dialects and a present wrong content-type still fail the open.
- **`dev peek` evaluates a triage model against a session's own verdicts** (docs/redaction-fork.md): `--triage-model` replays every gate under the separate-model shape and compares each draw line-for-line with what the session's peek kept — kept fractions, over- and under-retention, exact matches, phantom `none`s, a disagreement table with both notes, and `--out` for every row as JSON.
- **A separate triage model for the fork peek** (docs/redaction-fork.md): `--triage-model` runs every peek on its own client — own identity and persona over the session's context block, only the two peek tools, its own sticky key, thinking off unless `--triage-thinking` (`reasoning: {enabled: false}` on OpenRouter for a foreign model), the asked-for tool forced unless `--triage-auto-choice`, `--triage-effort` to turn the model down rather than off, and a peek-sized output cap; thinking-off is spelled per the model's `reasoning.mandatory` metadata; omitted or equal to `--model`, the peek borrows the agent's client as before. The `note` ask now says it is a note to self, and `+third-person` is an ask-variant ablation.
- **Responses replay is covered across consolidation and masking** (docs/consolidate.md, docs/env.md): a boundary that would cut a call from its result is refused at construction with an error result instead of folding an orphan into every later request; a masked `function_call` argument string is rewritten only when a value changed, so ordinary calls replay the provider's exact bytes.
- **Requests refuse a lossy dialect switch and an illegal tool name** (docs/transport.md, docs/tools.md): `Client::complete` and `dev wire` reject a recorded session whose assistant turns are in the other dialect instead of encoding a history with the replies dropped, and boot fails on a mounted tool name the dialect's alphabet or ceiling (128 Messages, 64 Responses) rejects, by display name; the Responses fork-peek frontier is pinned beside the Messages one.
- **The TUI names an executing Responses function call** (docs/tui.md): `in_flight_call` reads calls through the dialect-neutral accessor, so `background`/`kill` and the interrupt hint follow a Codex bash the same as a Messages one; unparseable arguments name nothing.
- **The Responses HTTP boundary is covered over a mock upstream** (docs/transport.md): headers, a 400 returning its body once, a 503 retried and recorded, and the ceiling cutting a partial stream; the retry set is checked against OpenAI's error guide, whose non-retryable 429 codes now class as terminal; `Usage::prompt_tokens` is the one prompt-total sum.
- **GPT-6 Astra is in the compiled OpenAI catalog** (docs/transport.md): exact window, output, and effort vocabulary, and a model that refuses `temperature` now fails an explicit `--temperature` at boot.
- **The spotter model defaults per provider** (docs/permissions.md): gpt-5.6-luna on the OpenAI arms, claude-haiku-4-5 elsewhere, so a bare OpenAI `serve` no longer fails on the Haiku default.
- **`usage.plan` publishes the Codex subscription windows** (docs/control-api.md): the plan type and the 5-hour and 7-day windows' used percentage, length, and reset instant, read off every Codex response including the 429 that ends a window; null on other providers.

### Fixed
- **Concurrent spawns no longer hand a child another command's stdout pipe** (docs/supervisor.md): every `Command::spawn` in the crate runs under one process-wide lock, closing the macOS window between `pipe()` and `FD_CLOEXEC` in which a spawn on another thread inherited the write end and a long-lived grandchild held the first command's output open until it exited.
- **Codex requests carry the sticky key on `session-id`, the header that backend actually reads** (docs/transport.md): the `openai-codex` arm sent the key only as the body `prompt_cache_key`, which the backend accepts and discards while minting a fresh per-request key, so the prefix cache was matched on luck; one workload measured twice went from 30%/40% warm (turns/peeks) to 80%/100%.
- **A distilled result's `kept N of M lines` is right when the transcript holds only its 16 KiB prefix** (docs/control-api.md): the entry view carries `distillate: {total_lines, kept_lines}` computed by the daemon over the whole content, and the web client labels from it; a body whose kept lines all lie past the prefix says so.
- **Single-entry reads validate with an `ETag` instead of `Cache-Control: immutable`** (docs/control-api.md): at a socket-root binding `/v1/log/:seq` is the same address for every session the origin serves, and the year-long lifetime returned another session's entry to the inspector; every successful GET now carries a content-hash tag and answers a match with `304`.
- **A quota, plan, credential, or invalid-request failure stalls on the first attempt** (docs/transport.md): the provider's error name is classed as terminal or transient, and a terminal one — inside the stream or as the Codex backend's `usage_limit_reached` 429 — stops the trajectory at once with `stall.reason: upstream_refused` instead of spending the twelve-attempt abort schedule on the same answer.
- **Codex requests replay the backend's `x-codex-turn-state` sticky-routing token** (docs/transport.md): the header is captured from the first response of a user turn, sent on every later request of that turn including fork peeks, and dropped at the next turn, as Codex CLI does; a session that omitted it paid for its prefix repeatedly as the cache missed. Requests also carry the `x-codex-routing-hint` model hint.
- **The TUI no longer dies on a control character in sidebar or strip text** (docs/tui.md): a background process whose command line held a newline (a multi-line `python -c`) hit ratatui's `cell_width` assertion on every frame, and again on every restart while the process lived; direct cell writes now fold control characters to `�` as the transcript already did.
- **The web client reads the ordered assistant entry** (docs/web-client.md): it still expected the grouped `thinking`/`text`/`calls` shape the log dropped with the Responses dialect, so any session crashed at first render; `session/assistant.ts` now derives that view from either dialect.
- **A tool call cut at the output-token cap is no longer dispatched** (docs/transport.md): a `max_tokens` completion carrying a `tool_use` block is a record-only partial whether or not its arguments happen to parse — the upstream had been repairing a truncated `write` into a valid object with no `path`.
- **An OpenRouter endpoint far below its peers no longer caps the session's output** (docs/transport.md): the `max_completion_tokens` min is taken over endpoints at or above a 32k floor, so one 2048-token outlier excludes itself from routing instead of holding every turn to 2048.
- **`max_tokens` is shrunk to what the window spares** (docs/transport.md): each request reserves `min(cap, context_length − estimated prompt − margin)` instead of the advertised cap verbatim, and a window-overflow 400 halves and retries — a 1M model advertising a 943k cap had walled every session at ~105k of prompt; `usage.context.limit` now reports the window less the reservation.
- **Session cost pricing backs off over minutes** (docs/transport.md): the generation lookup retries across 2s–300s instead of 2s/10s, so an upstream whose record lands late (`meta/muse-spark-1.3`, >60s) no longer leaves every request `unpriced`.

### Removed
- `efference host` and the per-session Unix-socket proxy (`trillium-proxy`): the host will own sessions in-process rather than forward to session processes. The `/sessions` gate surface and session-prefixed client routes stay.

### Changed
- Session preparation is `boot::prepare` in the library (docs/control-channel.md): the CLI's `serve` resolves flags into a `SessionRequest` and binds listeners; everything from config to client is reusable by a host.
- Session tasks are owned by a `SessionRuntime` under a child `Swansong` (docs/control-channel.md): the loop, watchers, background reaping, and scratch cleanup stop as one unit, independent of listeners; the loop runs on its own thread.
- Session boot snapshots the caller environment for provider/reference lookup, subprocesses, and masking; children no longer inherit extra host variables.
- Session policy, foreground/background commands, config loading, and environment-reference commands now use an explicit session working directory.
- Daemon boot takes explicit working/storage roots; usage and attachments no longer derive from the socket, and file serving uses the supplied session root.
- Rename the session state/control type from `Shared` to `Session`; execution and wire behavior are unchanged.
- **One handler construction** (docs/web-bind.md): `handler(transport, app)` in `src/daemon/handler.rs` is the only place a trillium stack is assembled — the socket, the TCP bind, the host, and every test mount it, with each transport-dependent layer an `Option`; the control routes are named `async fn`s under `src/daemon/http/`, one file per route family, and the three auxiliary routers are `mint_routes`, `enrollment_routes`, and `host_routes`.
- **`efference attach` is removed; `open`, `cache`, and `view` move under `efference dev`** (docs/operating.md): the TUI superseded the line REPL, the bootstrap-link mint is a credential-minting verb that must not ride the MCP-exposed `control` group, and the cache report is a developer's instrument until a client shows the rate. `open --qr` is gone pending a TUI or web onboarding flow.
- **One HTTP client per process** (docs/transport.md): the agent, provider metadata, MCP-over-HTTP, OAuth, web push, and the dev-proxy share one connection pool instead of eight — the turn stream and the generation-cost GETs now multiplex onto one OpenRouter HTTP/2 connection, and a spotter eval no longer opens a pool per case.
- **The bash fast-path parses with `brush-parser`** (docs/permissions.md), replacing a `yash-syntax` pinned to its last standalone version — same admitted shapes, same fail-closed posture, on a parser that tracks bash and still receives updates.

### Added
- **The CLI is three groups** (docs/operating.md): the top level holds only the human verbs; the twelve session-control verbs move to `efference control <tool>`, written once as mcplease tools and served over MCP by `efference mcp` from the same definition (with per-tool `session` overrides, `timeout_s` on the waits, and behaviour hints for a mounting harness's approval UX); the development instruments move to `efference dev <verb>` behind a default-on `dev` cargo feature.
- **Direct OpenAI inference over the Responses API** (docs/transport.md): `EFFERENCE_PROVIDER=openai` selects the Responses wire dialect — stateless replay with `store: false`, encrypted reasoning and message `phase` replayed as returned, explicit cache markers on GPT-5.6, usage restated into the harness's three-way split. Projection is now a dialect-neutral semantic fold plus one encoder per wire (docs/log-and-projection.md); the assistant log entry keeps each provider's ordered output rather than grouped thinking/text/calls, and pre-shape logs were migrated once by `scripts/migrate-assistant-output.py`.
- **`EFFERENCE_PROVIDER=openai-codex` bills a ChatGPT/Codex subscription** (docs/transport.md): the Codex backend over the same Responses dialect, authenticated with the token Codex CLI caches in `~/.codex/auth.json`, request shaped exactly as Codex CLI's.
- **Every outbound request identifies the harness** (docs/transport.md): a `User-Agent` of `efference/<version> trillium-client/<version>` on every host, plus OpenRouter's app-attribution headers (`HTTP-Referer`, title, `cli-agent,programming-app`) on the inference POSTs alone — `Referer` means something else to every other host.
- **`efference check [path]`** (docs/operating.md): validate a config template offline — the boot-time parse and soundness checks plus `[context]` resolution — and print its grants and preamble size; the new-project guide names it as the terminus of a "set this project up" task, and the scaffolded no-config session grants it. Now also mounts every `[mcp.servers.*]` stanza and reports each server's advertised tools against the file's `tools` grants (stored credentials reused, authorization never started here); a required server that does not mount fails the check, same as boot.
- **The new-project guide asks before it writes** (`efference://guide/new-project`): survey the workspace, then end the turn on a draft and the decisions that are the operator's — grant breadth, withheld built-ins, MCP servers, preamble contents, `scope`; the starter template grants `"efference.*"` and the guide enumerates what that covers; it drafts an `AGENTS.md` for the preamble rather than listing the README; the session preamble now says that a decision the workspace cannot answer is asked by ending the turn on it.
- **Effort validates against the model's declared levels** (docs/transport.md): `--effort`/`[transport] effort` are strings end to end — no local vocabulary, the model's `reasoning.supported_efforts` (OpenRouter's singular model-entry route, fetched at boot and fatal there like the ceilings route) is the list — so an undeclared level is refused at boot with the supported list instead of OpenRouter's silent nearest-mapping, a model declaring no levels refuses any configured level, and the boot line prints the provider default when effort is unset (the 2026-08-29 no-op-flag incident); Anthropic declares no levels and passes through, and the `xhigh`/`max`-with-thinking-off boot refusal stands.

- **Web push on gate and settle** (docs/web-push.md): each live daemon notifies subscribed devices when an approval gate opens (body: the call's `intent`) or a turn settles (body: the turn's closing prose) — VAPID key derived from the machine root, subscriptions in one machine-scoped store, opt-in checkbox in the web client's Interface tab.

- **No push while the session is watched** (docs/web-push.md): a live `/events` connection suppresses gate and settle notifications; the web client drops its stream a few seconds after the tab goes hidden and resumes from its cursor when it returns, `?presence=off` opts a non-human consumer out of the count, and the service worker skips a notification a visible window would duplicate.

### Fixed

- Committed thinking keeps the line structure the model emitted. It also means the block no longer changes shape when the turn commits, since the live thinking phase already rendered line by line.
- Scrolling up during a stream stays where it was put. A re-projection drops the layout cache, and the event loop re-projects before draining an input burst, so a scroll arriving mid-stream saw no layout — and `max_scroll` answering 0 there made every scroll read as "at the bottom", re-arming stream-following and snapping the viewport to the end from wherever was being read.
- Wrapping a long line is linear in its length rather than quadratic: the wrap policy measured the whole remaining text once per row emitted, purely to test whether it fit. One 16k-column line (a tool call's JSON input mid-stream, a minified file) cost ~300ms per wrap in release, repeated every frame while it streamed.
- The live tail no longer renders a blank row between every line: an entry separates its child *blocks* by a blank row, and streaming tool output, thinking, an arriving tool input, and a pending user turn each modelled one source line as one block.
- Streamable-HTTP requests carry the `Mcp-Method` and `Mcp-Name` headers `2026-07-28` requires, with the spec's base64 sentinel encoding for values that cannot ride raw. Their absence was invisible against mcplease-backed servers, which do not validate them, and rejected by Sentry with `HeaderMismatch`.
- An MCP server name may no longer contain `__`; the separator inside a name would move the namespace boundary that the wire→display and dotted-config→wire mappings both resolve as the first occurrence.
- Tracks the published mcplease 0.3 API (`Dispatch::call` with a `RequestContext`); embedded tool results now fold through the same `CallToolResult` renderer as connected ones, and an interim (`input_required`) result from a connected server lands as a named error instead of an empty success.

- Token usage merges `message_start` and `message_delta` per field, so OpenRouter turns report real input and cache read/write counts instead of the all-zero `message_start` placeholder.
- The fork peek's ask is scoped to the results of the gate it opened, and a single-result gate asks for a bare `keep`/`note` with no call id; an unbounded ask had models re-triaging the whole transcript against prior results' `[seq]` tags, failing coverage and withholding output.
- A coverage rejection records which ids the verdict *did* answer, so a scoping failure is distinguishable from an empty verdict in the log.
- The fork peek sends the agent turn's exact request envelope (shared tools array, `tool_choice: auto`, same thinking policy), so peeks read the agent lineage's prompt cache instead of re-writing the transcript cold on every gate.
- The trailing cache breakpoint marks the last *text* block — a marker on a `tool_use`/`tool_result` block bills an unreadable cache write on OpenAI-fronted endpoints.

### Added

- `GET /log` takes bounded windows — `?tail=N` (exactly N, cut anywhere) to open cold at the tail, `?before=<seq>&tail=N` to page backward; `since` with `tail` is a `400`.

- Every non-2xx response carries a typed envelope (`{code, message, detail?}`), with one canonical status per code.

- Processes are a REST resource: `GET /processes` (+ `/:id`, `/:id/output?since=` cursor reads), `PATCH /processes/:id` (`muted`, and `background: true` as the foreground→background handoff with an optional note — replacing `POST /background`), `DELETE /processes/:id` (kill).

- The write routes are resources: `POST /turns`, `POST /notifications` + `DELETE /notifications/:id`, `PATCH /proposals/:seq {state}`, and `GET`/`PATCH /loop` absorbing the pace and review-level verbs (one call can move both dials), with `POST /loop/interrupt` the loop's one remaining verb.

- `GET /state` is composed from one function per state topic and its keys are named for those topics, so the snapshot and the level-triggered `state` frames cannot drift.
- The TUI composer supports grapheme-safe text selection, mouse selection, and plain-text copy, cut, and paste with a process-local clipboard fallback.

- `[context]` grants through policy: a listing is itself a read grant (reads of listed paths fast-path clear with no other config); `update` clears writes to existing files under an entry, `create` to new ones — `create` without `update` is an append-only store.
- `[context]` exec sections: `Label = { exec = "…" }` runs once at boot (`bash -c`, session cwd, 10s timeout, process-group kill on hang) and its stdout becomes a preamble section at its document-order position, frozen + snapshotted like static files; fails closed on spawn/exit/timeout/non-UTF-8.
- `[context]` dirs walk recursively (hidden children skipped, symlinks followed with a cycle guard), so a Claude-Code skills tree (`skills/<name>/SKILL.md`) lands as one listing per skill; frontmatter handles YAML block scalars (`description: >-`) and nested maps can't pollute top-level keys.
- Mid-trajectory turn interjection (seam-drain): a user turn submitted while the loop is running no longer waits for the whole trajectory to end — the loop drains the turn inbox at each juncture (`Frontend::drain_injected_turns`) and appends each as a canonical, undismissable `Payload::User`; `project` merges a user turn that follows a turn's `tool_result`s into one role-alternating message `[tool_result…, text]` (the redirect steer now uses this deterministic merge instead of relying on the server). The TUI echoes a submitted turn immediately as a dimmed `⋯` pending unit, resolved to a committed turn when its `User` entry streams back — a faithful "now on the wire" delivery indicator.
- Pace and hold: an operator-view wall-clock pacing dial, transparent to the agent — a `(speed, held)` state applied as an interruptible daemon-side sleep at the between-turns seam (`Shared::pace_at_seam`), never logged or projected, so a held/slowed loop is byte-identical on the wire to a fast one. `held` is a pause overlay that retains the speed underneath (resume returns to it; a submit always resumes and delivers immediately). Driven by `POST /pace {speed_ms?, held?}` / `efference pace` and reported in `GET /state`; the TUI shows a loud `⏸ HELD` / `⏱ 10s` status-bar indicator with `+`/`-` speed and `p` hold keys.
- Graduated Esc: `Esc` in the TUI is a *state machine* (not a mode toggle, not a press-count) — each press's effect follows the current state: not-at-rest-composer → return to composer; then at the composer, held → interrupt the tool (`POST /interrupt`), loop-active → pause/hold, idle → swallow. So from the composer one `Esc` pauses and a second interrupts, with no wasted press and no timer/reset. "Loop active" reads a new `GET /state` `running` flag (unioned with streaming) so `Esc` reaches a *silent* runaway tool. Pure TUI keybinding over the existing `/pace` and `/interrupt` affordances; the `?` help now lists the pace/interrupt keys.
- Runtime review-level dial: the boot-time `--autonomous` bool becomes a runtime-settable `ReviewLevel` (`autonomous` / `spotter_human` / `human_only`) over `POST /review-level` / `efference review-level`, reported on `GET /state` (with `autonomous` kept as a derived mirror). `human_only` skips the spotter entirely (no tokens, no `Spot` entry) and gates every residual call straight to the human, who grows the allowlist by hand via the existing self-authorizing `.allow` (approve-always-at-prefix) grant — so learning is relocated, not lost. The TUI POLICY sidebar shows the current level (read-only; the gear selector is deferred).
- Foreground→background handoff: `POST /background` / `efference background [--note]` / the TUI's `b` key detach a running foreground bash command into the supervisor as a `bg#<n>` process — no output lost (the capture is seeded with everything already streamed), the `tool_use` paired with a non-error handoff result, the optional note delivered as the next user message. The interrupt intent is now typed (`Interrupt::Kill` / `Detach`); `Ctrl-C`/`Esc` kill semantics are unchanged.
- TUI control strip: a one-row, always-present surface between transcript and composer showing the currently relevant loop verbs as focusable, clickable button-like items with their fast-path keys (per state family: gate → approve; held → resume/slower/faster/kill; running → pause/background/kill; idle → theme/help; `detach` pinned right) — one `↑` from the composer, ranked left→right by relevance, fit-to-width. The focus axis is now transcript → strip → composer.
- Gate affordances on the strip: `approve ⏎ · allow… · abort` with a dim redirect note; `allow…` is a *stager* — it parks the draft, pre-fills the derived grant spec under an `allow` prompt chip for editing, `⏎` commits through the `.allow` path and restores the draft, `⎋` cancels (the new gentlest Esc rung). The inline gate hint and status bar stop advertising the typed `.allow`/`.abort` forms (the strip is the legend; the sentinels remain as mechanism).
- TUI block menu: the focused transcript unit's per-entry verbs (`expand`/`collapse`, `raw`/`distilled`) as focusable, clickable button-like items trailing its header line, travelling with `↑`/`↓` focus — `←`/`→` choose, `⏎`/click fires (the collapse toggle leads, so `⏎` still expands). The new home for the `r` raw flip. A prose turn, a live tool's in-flight output, and the gated exchange carry none (the gate's verbs are on the strip).
- TUI bind purge: the transcript-navigation single-letter verb binds (`p` pause, `+`/`-` pace, `b` background, `r` raw, `t` theme) are gone. The verbs now answer only where they are shown — on the control strip as **scoped mnemonics** (a shown item's letter fires it while the strip is focused; `p` in the held set, `b` in the running set, `t`/`?` when idle) or by click, and the raw flip on the block menu — so a plain letter in the transcript never fires a buried verb, and the status bar stops enumerating verb keys (the strip is the legend). Navigation/utility keys (`j`/`k`, `g`/`G`, `m`, `?`/`h`, `q`) and graduated Esc are unchanged.
- TUI pace widget: the strip's *widget* item class. `⏎` on the held set's `pace` item enters an inline stepper (`▴ pace <v> ▾`, loud, owning the row) where `↑`/`↓` step the between-turns dial in place — each step previews by moving the live pace without pushing to the daemon, `⏎` commits the previewed speed, `Esc` reverts to the entry value (the gentlest rung of graduated Esc, nothing sent to unsend). Replaces the earlier `slower`/`faster` buttons, so between-turns pace is adjusted only here, only while held.
- TUI strip contents model: one relevance-ordered list per state, filled to the width and cut from the right, with an omnipresent dimmer tail (`pace · theme · help · detach`) that is therefore cut first — `pace` most protected, `detach` least, each with a keyboard fallback. Only verbs that apply are shown: `background`/`kill` are foreground-`bash`-only (the handoff adopts a live child; `kill` races an abort future no other backend awaits — the `interrupt` entry below since made the interruption half universal), `pace` is reachable in every state rather than only while held, and `held` is a modifier that renames the hold verb to `resume` wherever it appears. Which tool is running is read off the committed log — the last call with no paired result — so no daemon round-trip was needed. Replaces the fixed per-state-family sets and the right-pinned `detach` universal.
- `interrupt` — `POST /interrupt` now **latches** (`AtomicBool` consumed at the junctures either side of a call), so it reaches tools nothing can suspend: the loop stops and the in-flight call's output is withheld from the model, kept in the log with `wire: Elided` (its first construction site) and never sent through the redaction fork. Taken before a call runs it stops the turn instead. The strip carries it in every active state — labelled `kill` on a foreground bash, where it also kills the process group — replacing the state that offered no interruption verb at all.
- Per-session scratch dir: `serve` mints a private `$TMPDIR` (mkdtemp-style, mode 0700), exports it to every bash child (foreground and background), always grants it rw, and cleans it up on session end (`--keep-scratch` retains it). Structured tool paths expand `$TMPDIR`/`${TMPDIR}` at one choke point upstream of classify/spot/exec (frozen boot-time map, allowlist starts at exactly `{TMPDIR}`, unlisted names hard-error — never expand-to-empty); the spotter's scope block aliases `$TMPDIR` to the granted path so bash scratch writes are judgeable.

### Changed
- **One handler construction** (docs/web-bind.md): `handler(transport, app)` in `src/daemon/handler.rs` is the only place a trillium stack is assembled — the socket, the TCP bind, the host, and every test mount it, with each transport-dependent layer an `Option`; the control routes are named `async fn`s under `src/daemon/http/`, one file per route family, and the three auxiliary routers are `mint_routes`, `enrollment_routes`, and `host_routes`.
- The session's config file is no longer named up front in the preamble — that high-salience "here's what you're allowed to do" pointer drew sessions into reading and probing their own perimeter as a first move. The perimeter stays out of attention; the gate-rejection message names the config as the request channel only when a move actually strays.
- Orientation is config, not code: the hardcoded environment block (cwd/platform/project-type, `env::orientation` + marker detection) is deleted; *where the session is* is now an ordinary `[context]` exec entry — the config-less scaffold ships `"Environment at boot" = { exec = … }`, and a written config owns the whole preamble.
- Model selection moved to a per-session `serve --model <id>` flag (default `claude-haiku-4-5` for dev).
- Tool definitions unified into one source shared by the loop, the keepalive ping, and the dev `wire` view (closing a cache-correctness gap).
- The distilled-note prefix changed from an em-dash (`— `) to the `⟢` provenance sigil already used by surfaced-context lines, so a surviving triage note is honestly signed as harness-curated output without invoking mechanism vocabulary. Render-layer only; the fork's `note` schema is unchanged.

### Fixed
- **A distilled result's `kept N of M lines` is right when the transcript holds only its 16 KiB prefix** (docs/control-api.md): the entry view carries `distillate: {total_lines, kept_lines}` computed by the daemon over the whole content, and the web client labels from it; a body whose kept lines all lie past the prefix says so.
- Fast-path permission grants no longer misfire on two dogfood-caught cases: a trailing fd-dup redirection (`cmd 2>&1`) stays on the bash fast path (only *file* redirections gate now), and a batched `read` spanning both `[paths]` and `[context]` grants clears per-path across the union instead of gating.
- Guard against runaway tool results overflowing the request (400 on oversized content).
- Streamed control characters, a turn-loop livelock, and a resume edge case.
- Extended thinking, end to end: the assembler folds streamed `thinking`/`redacted_thinking` blocks (signatures preserved) into leading assistant content, `project` renders them first on the wire, and the request's `thinking` field rides on `tool_choice` (main turn `auto` → adaptive+summarized; the fork's forced choice and the keepalive → disabled, the one illegal pairing made unrepresentable). Replaces the earlier thinking-disabled stopgap; thinking blocks are stored verbatim, not yet elided.
- A config edit that no longer parses fails loud, not silent: reload keeps last-good policy (fail-closed) and raises a `config-parse-error` notification naming the error, so the session learns its edit didn't take instead of thrashing. Schema-teaching headers on `efference.toml` + the config scaffold lead with the `scope`-is-a-string anti-footgun.
- Thinking is kept, not just streamed past: a committed turn's extended thinking renders as a collapsible block at the head of the turn (opening paragraphs always visible, expand for the rest, keyed by `seq` so the toggle survives re-projection) — reasoning streams too fast to read live, so the transcript holds the copy a human actually reads.
- A turn that produces no prose is visibly working: the streaming sink is typed (`Streamed` — text / thinking / tool-call-open / tool-input), so thinking and a tool call's arriving arguments reach clients as their own `/stream` events instead of not at all, and the TUI renders the live phase in full — the thinking so far, or `❯ calling <tool>…` over its JSON input as it accumulates — superseded by prose, by the next phase, and by the committed turn. The serve log prints `(generating — turn N)` before blocking on the model, so its last line is no longer a stale `idle` that reads as finished.
- Every committed grant is written to the session's config file, so that file is a complete record of the perimeter the session ran under — the artifact an operator reads and copies grants up from. `Lifetime` (`session`/`persist`) is retired: it had been drained of meaning by per-session config dirs, and every live caller hardcoded `session`, so the write-back had never run outside tests. A failed write now fails the grant rather than silently degrading it to session-only.
- A config edit is now adopted or reverted, never approved-but-inert: the session's config file is held in memory as a format-preserving TOML document under the invariant that the disk always holds the last content that parsed, so a write that doesn't parse is undone (comments and key order intact) and comes back to its author as an error naming the parse failure — the same rule for a gated tool write and an operator's hand-edit alike.
- A gate is always visible, whatever the call's length: its spotter reason, affordance, and `⏸` marker render as siblings of the exchange rather than inside its collapsible body, where a command more than a few lines long had been clipping the whole gate off screen. Structured annotations *about* a call now sit beside the exchange; the collapsible body holds only agent-generated content.
- The spotter's verdict renders beside every call it judged, stance first (`spotter cleared · …` / `watching` / `gated`), in the dim register — cleared calls included, which are most of them and previously had no surface at all, and resolved gates, where the verdict is the only record that a human overrode the spotter.
