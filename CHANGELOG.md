# Changelog

All notable changes to efference. Format follows [keep-a-changelog](https://keepachangelog.com);
one line per feature. The project is private and unreleased, so everything lives under
*Unreleased* for now. For how the system works, see [`docs/`](docs/); for the narrative
behind a change, see [`journal/`](journal/).

## [Unreleased]

### Changed
- TUI transcript is a flat sequence of typed entries (message / thinking / call / result /
  annotation) rendered **whole** — the 8-line collapse budget, the expand toggle, and the
  turn container are gone; a call and its result are separate, independently focusable units.
- Code blocks highlight and show their `❬lang❭` tag only when the language is known — untagged
  tool output is no longer labelled and coloured as Rust (a ferritin rustdoc default).
- A distilled result renders its kept lines with dimmed original line numbers, gaps implied by
  the jump, in place of the wire's `@@ lines a-b @@` headers; the distiller's note and the
  pre-triage truncation breadcrumb are their own annotations beside the result, not lines in it.

### Fixed
- A tool with its own representation (the diff tools, `read`) renders its full output through
  it rather than the triaged form, so a distilled edit result is a colored diff again instead of
  verbatim text with a bare `===DIFF===` line in it; where triage dropped lines, the transcript
  says the agent's copy kept fewer. Edit calls name the file and the operation
  (`edit · src/tui/composer.rs · replace`) in place of a 48-character anchor fragment.
- Code-block content wraps to the box's inner width instead of spilling past the right border
  and being clipped there — through the same `wrap_points` break policy prose already used.
- Code-block columns are measured in display width, not bytes: a highlighted line containing
  multi-byte characters no longer pushes its later tokens right (`├── anyhow v1.      0.86`).

### Added
- `write` calls render as the file they write: path inline, contents as a syntax-highlighted
  code block, instead of a JSON envelope with the body as one escaped string.
- `efference view <session>`: open a recorded session's `log.jsonl` in the TUI, read-only — no
  composer, no loop verbs, no sidebar, no socket.
- TUI transcript as a materialized view: the projection splices only the entries whose calls
  changed, layout is cached per node, and a measure pass pins the stream-following viewport
  before a single paint — a streamed frame now costs the viewport, not the log.
- Batched triage gate: a completion's calls all run before one fork peek triages their
  results together, so a provider that ignores `disable_parallel_tool_use` no longer
  orphans the peek's request (which silently put uncurated output on the wire).
- Append-only annotated log + byte-stable deterministic projection — the context substrate.
- Durable JSONL persistence of the log, resumable across restarts.
- Universal redaction fork: every tool result is distilled at append; raw output never reaches the wire.
- `retain` verdict (`all` / line ranges / `none` + note) stored as the wire form and re-rendered as `@@`-hunk output each turn.
- `Triage` audit entries — every fork verdict (and its origin) is reconstructable from the log.
- Visible `[seq]` block handles on tool results for re-read / branch / compare addressing.
- Trajectory consolidation: agent-called `consolidate(summary)` + `Mark::Boundary` projection fold, with branch-from-seq.
- Ambient-notification inbox: out-of-band `POST /notify`, enqueue-then-triage at the fork gate (pin / dismiss / leave), logged at first-show.
- Context surfacing: the fork peek offers a roster of unloaded `[context]` items; the model's `surfaced` verdict rides the `Triage` and projects as a read-me reminder at the Triage position (structured listing snapshotted additively in the `Preamble`).
- Background-process supervisor: `bash background:true`, live peek tail, directed `list_processes` / `read_process` / `kill_process`, and idle-triggered triage (wake-on-notification).
- Control channel: HTTP-over-Unix-socket daemon (`serve` / `turn` / `approve` / `interrupt` / `state` / `log` / `attach`) with durable `/events` and lossy `/stream`.
- Three-valued approval gate (approve / abort / redirect) over the `Frontend` trait; multi-turn headless via `POST /turn`.
- Upstream SSE streaming with token-level deltas, cache instrumentation, and a `max_tokens:0` keepalive.
- In-process MCP tools (fs-mcp, semantic-edit-mcp) reusing the generated `mcplease` tool enums.
- `read` tool line-range support (via `from_line` and `to_line` arguments) in `fs-mcp`.
- Interactive TUI (`efference tui`): themed streaming transcript, conversational rendering with per-tool result renderers, emacs-keybind composer, inline approval gates, and a live background-process panel.
- `Screenplay` snapshot harness + `efference gallery` for iterating TUI display without being blind.
- TUI dev tooling: a `Ctrl-S` dev screenshot keybind (`EFFERENCE_DEV`) dumping the live screen as the same framed character grid the snapshots use, and a log-replay harness (`Screenplay::replay` over a recorded `.efference/*.jsonl`) so snapshot states are reachable-by-construction; one shared `frame_grid` encoder backs both.
- TUI focus model: every block is a focus unit — each prose turn and each exchange (long or short) — shown by a glyph `▌` bar down the focused unit; `↑` spills from the composer's top edge into the transcript (with a `0,0` detent), `↓` past the last unit falls back, and `Esc` always returns to the composer. Contextual keymap (same physical key, context-dependent meaning); `C-d` on an empty composer quits.
- Config (TOML via `toml_edit`): `serve --config <path>` / `efference.toml`, a string-keyed schema (`scope`, `watch-for`, `[commands]`, `[paths]`, `tools`) validated fail-closed (command keys lexed; non-simple keys reject the file), a session `scope` that folds byte-stably into the cached preamble, resolved path reported on `GET /state`.
- Permission fast-path: deterministic, zero-model-cost auto-approval of allowlisted bash — a `yash-syntax` structural-simplicity check (single simple command, no operators/redirection/expansion/glob) then a token-wise `[commands]` prefix match; everything else falls through to the gate.
- Spotter permission rung: an independent, fresh-context model (Haiku band) judges the calls the fast-path can't clear, returning a graded `clear`/`watch`/`gate` stance + one-line reason; verdicts logged as `Spot` audit entries, scope drawn from the config's `[paths]` grants, persona in `assets/prompts/spotter.md`, fail-closed to the human gate. `efference spotter` exercises it on one `(scope, watch-for, command)`.
- Nested path carve-outs: `[paths]` resolution is longest-prefix-wins, so a no-access (`false`) grant denies a subtree within an allowed parent; `serve` injects a self-surface stack (deny `.efference/`, re-allow this session's `config.toml` read-only) so a session can't write its own log or poke its own control socket, and the deny layers render into the spotter context so bash gates on them too.
- Spotter persona: a request to a unix-domain socket is judged as local IPC (on scope/opacity), not conflated with network egress to an external host — so driving an in-scope local socket no longer false-gates as irreversible egress.
- Config edits: a `Payload::ConfigEdit` (a `ConfigChange` over `command`/`path`/`tool`/`scope`, `session` or `persist` lifetime) folds into an effective config by replace-at-key (last-write-wins, materialized from the ordered log); the orchestrator commits one at a gate with a fourth `Approval::ConfigEdit` decision, which re-classifies the call against the new policy (it runs only if the changed rule clears it — never an unchecked ride-along) and auto-persists to the TOML file (format-preserving, comment-safe, any key including a `scope` narrowing) when asked.
- Proposals client surface: `GET /proposals` + `POST /proposals/:seq` (commit/cancel) over the control channel, the queue mirrored in `/state`, and `proposals`/`commit_proposal`/`cancel_proposal` client verbs — so an orchestrator-above can resolve the async config-edit proposals (prefix-promotion, the session's config-write) that previously accumulated with no client path. Commit folds the change into the effective config; cancel is audit-only.
- Spotter reason at the gate: a held call's `/state` now carries the spotter's one-line reason, read from the `Spot` audit entry the spotter logs before routing to the human — so the client can show *why* a call gated.
- TUI sidebar (right-docked when wide): `PROCESSES` (moved off the bottom strip), `STATS` (moved off the status bar), and `POLICY` — the live perimeter (scope/commands/paths/tools) with pending proposals rendered as tentative `⊕` lines in their sorted position. The sidebar's `Rect` backs an `Alt-S` sidebar-only screenshot slice (narrow capture); resize now repaints immediately.
- Gate enrichment: the spotter's reason renders inline at the gate, and `.allow [prefix]` adds a rule (an `Approval::ConfigEdit`) then re-runs the call iff it now clears — bare `.allow` derives the grant from the gated bash program or the tool name.
- Session-visible config edits notify: a committed `scope`/`paths` edit raises an `Ambient` notification (optional tail append, reusing the inbox/triage machinery) so the session learns its perimeter moved — never re-rendering the frozen cached preamble; `commands`/`tools` edits reach the model only through the classifier.
- Config-edit lifecycle: a `ConfigEdit` carries a `state` (`proposed`/`committed`/`cancelled`) + `resolves` — only committed edits fold; a proposal parks inert in a pending-proposals queue until an orchestrator commits/cancels it.
- Live config reload: an external edit to the session's config file takes effect without a restart — a debounced fs-watcher (`notify`) diffs the file and emits committed config-edits, fail-closed on a malformed file (last-good policy stands).
- Config-as-a-reviewed-file: the session edits its *own* per-session `config.toml` (snapshotted from the origin at boot, named in its preamble) to request a permission change; a write to that file is forced to the operator gate (bypassing fast-path and spotter), and on approval fs-watch folds it — replacing a bespoke propose-config tool with native file editing, and making "session-only" a matter of geography.
- Per-session directories: each `serve` runs in `.efference/<id>/` (`--name`, else a timestamp id) holding a colocated control socket, log, and config; client verbs find the daemon by `--name` or by scanning for the single live socket.
- `/settle` long-poll (+ `turn --wait` / `approve --wait`): block until the daemon reaches a decision point — a gate, or idle — then return `/state`, so a client drives it synchronously instead of polling.
- `GET /state` reports the full *effective* policy in force (scope, watch-for, commands, tools, paths), not the boot config — an orchestrator reads a subordinate's live perimeter from it.
- Autonomous mode (`serve --autonomous`): with no synchronous human at the gate, a spotter `watch`/`gate` becomes a redirect that hands the call back to the model (pointing it at its config file to request access) instead of blocking; a config-file write still gates, held for the orchestrator-above. `autonomous` reported on `GET /state`.
- `wire --messages`: a config-independent messages-only view — prints just `project(log)` (+ trailing breakpoint), skipping the `system` + `tools[]` envelope, so it reads a session whose `config.toml` doesn't parse.
- Provider seam (`api::Endpoint`): endpoint URL + auth are resolved once from the environment — `EFFERENCE_ENDPOINT`, `EFFERENCE_API_KEY` (raw secret), `EFFERENCE_AUTH_HEADER` (default `x-api-key`), `EFFERENCE_AUTH_PREFIX` (e.g. `"Bearer "`); falls back to `ANTHROPIC_API_KEY` as `x-api-key`. The secret is kept alone (header/prefix split off) so it stays a whole-value `op://…` reference `op run` can resolve. Any Anthropic-Messages-compatible endpoint — notably **OpenRouter** (`/api/v1/messages`, `authorization: Bearer …`, provider-scoped slugs) — works with no code change. `supports_adaptive_thinking` becomes a Claude allowlist (foreign models get no `thinking` block), overridable with `EFFERENCE_THINKING=adaptive|off|auto`.
- OpenRouter skin tolerance (live-verified against `thinkingmachines/inkling`, full agentic loop incl. tool use): `Usage` token counts accept an explicit `null` (OpenRouter sends `cache_*: null` where Anthropic omits it — `#[serde(default)]` covered only absence, so a present `null` crashed the first turn with `invalid type: null, expected u64`); the assembler recognizes the trailing OpenAI-style `[DONE]` stream-end sentinel as terminal instead of tripping loud-on-unknown.
- `efference spotter-log` dev survey: reads the `Spot` audit entries back out of the session logs — a stance-distribution summary (with fail-closed rate) plus each verdict correlated to the call it judged and its one-line reason — across all `.efference/*/log.jsonl` or one session; `--stance`/`--no-fallback` filter, `--summary`/`--list` pick a half. The read-side companion to `efference spotter`.
- Prefix promotion: the harness learns its allowlist by probing. A frequency-gated, shortest-first descent rides one yes/no on each spotter call — the stance gains `clear_always` (clear the move *and* vote the offered prefix blanket-safe), recorded on the `Spot` entry and folded into a probe ledger; `K` safe-votes file a `Proposed(Command)` for an orchestrator to confirm. Soundness is exact-match + recurrence + judge-consensus (no fuzzy matching, no command-granularity cap).
- `[context]` preamble builder: the operator declares what the session boots knowing in `efference.toml` — bare paths and labeled groups of markdown files, mode (inlined body vs. listed stub) picked by each file's frontmatter, rendered as pseudo-XML name tags into the frozen system prompt after orientation. No auto-discovery; skills-compat falls out of frontmatter `name`/`description`.
- Boot preamble snapshot: `serve` appends the full rendered system prompt to the log once at boot (`Payload::Preamble`, projects to nothing), keeping the log the complete record now that the preamble folds in drifting file contents; `efference wire` shows the recorded preamble instead of a rebuild.
- `[context]` grants through policy: a listing is itself a read grant (reads of listed paths fast-path clear with no other config); `update` clears writes to existing files under an entry, `create` to new ones — `create` without `update` is an append-only store.
- `[context]` exec sections: `Label = { exec = "…" }` runs once at boot (`bash -c`, session cwd, 10s timeout, process-group kill on hang) and its stdout becomes a preamble section at its document-order position, frozen + snapshotted like static files; fails closed on spawn/exit/timeout/non-UTF-8.
- `[context]` dirs walk recursively (hidden children skipped, symlinks followed with a cycle guard), so a Claude-Code skills tree (`skills/<name>/SKILL.md`) lands as one listing per skill; frontmatter handles YAML block scalars (`description: >-`) and nested maps can't pollute top-level keys.
- Mid-trajectory turn interjection (seam-drain): a user turn submitted while the loop is running no longer waits for the whole trajectory to end — the loop drains the turn inbox at each juncture (`Frontend::drain_injected_turns`) and appends each as a canonical, undismissable `Payload::User`; `project` merges a user turn that follows a turn's `tool_result`s into one role-alternating message `[tool_result…, text]` (the redirect steer now uses this deterministic merge instead of relying on the server). The TUI echoes a submitted turn immediately as a dimmed `⋯` pending unit, resolved to a committed turn when its `User` entry streams back — a faithful "now on the wire" delivery indicator.
- Pace and hold: an operator-view wall-clock pacing dial, transparent to the agent — a `(speed, held)` state applied as an interruptible daemon-side sleep at the between-turns seam (`Shared::pace_at_seam`), never logged or projected, so a held/slowed loop is byte-identical on the wire to a fast one. `held` is a pause overlay that retains the speed underneath (resume returns to it; a submit always resumes and delivers immediately). Driven by `POST /pace {speed_ms?, held?}` / `efference pace` and reported in `GET /state`; the TUI shows a loud `⏸ HELD` / `⏱ 10s` status-bar indicator with `+`/`-` speed and `p` hold keys.
- Graduated Esc: `Esc` in the TUI is a *state machine* (not a mode toggle, not a press-count) — each press's effect follows the current state: not-at-rest-composer → return to composer; then at the composer, held → interrupt the tool (`POST /interrupt`), loop-active → pause/hold, idle → swallow. So from the composer one `Esc` pauses and a second interrupts, with no wasted press and no timer/reset. "Loop active" reads a new `GET /state` `running` flag (unioned with streaming) so `Esc` reaches a *silent* runaway tool. Pure TUI keybinding over the existing `/pace` and `/interrupt` affordances; the `?` help now lists the pace/interrupt keys.
- Runtime review-level dial: the boot-time `--autonomous` bool becomes a runtime-settable `ReviewLevel` (`autonomous` / `spotter_human` / `human_only`) over `POST /review-level` / `efference review-level`, reported on `GET /state` (with `autonomous` kept as a derived mirror). `human_only` skips the spotter entirely (no tokens, no `Spot` entry) and gates every residual call straight to the human, who grows the allowlist by hand via the existing self-authorizing `.allow` (approve-always-at-prefix) grant — so learning is relocated, not lost. The TUI POLICY sidebar shows the current level (read-only; the gear selector is deferred).
- Foreground→background handoff: `POST /background` / `efference background [--note]` / the TUI's `b` key detach a running foreground bash command into the supervisor as a `bg#<n>` process — no output lost (the capture is seeded with everything already streamed), the `tool_use` paired with a non-error handoff result, the optional note delivered as the next user message. The interrupt intent is now typed (`Interrupt::Kill` / `Detach`); `Ctrl-C`/`Esc` kill semantics are unchanged.
- TUI control strip: a one-row, always-present surface between transcript and composer showing the currently relevant loop verbs as focusable, clickable button-like items with their fast-path keys (per state family: gate → approve; held → resume/slower/faster/kill; running → pause/background/kill; idle → theme/help; `detach` pinned right) — one `↑` from the composer, ranked left→right by relevance, fit-to-width. The focus axis is now transcript → strip → composer.
- Gate affordances on the strip: `approve ⏎ · allow… · abort` with a dim redirect note; `allow…` is a *stager* — it parks the draft, pre-fills the derived grant spec under an `allow` prompt chip for editing, `⏎` commits through the `.allow` path and restores the draft, `⎋` cancels (the new gentlest Esc rung). The inline gate hint and status bar stop advertising the typed `.allow`/`.abort` forms (the strip is the legend; the sentinels remain as mechanism).
- TUI block menu: the focused transcript unit's per-entry verbs (`expand`/`collapse`, `raw`/`distilled`) as focusable, clickable button-like items trailing its header line, travelling with `↑`/`↓` focus — `←`/`→` choose, `⏎`/click fires (the collapse toggle leads, so `⏎` still expands). The new home for the `r` raw flip. A prose turn, a live tool's in-flight output, and the gated exchange carry none (the gate's verbs are on the strip).
- TUI bind purge: the transcript-navigation single-letter verb binds (`p` pause, `+`/`-` pace, `b` background, `r` raw, `t` theme) are gone. The verbs now answer only where they are shown — on the control strip as **scoped mnemonics** (a shown item's letter fires it while the strip is focused; `p` in the held set, `b` in the running set, `t`/`?` when idle) or by click, and the raw flip on the block menu — so a plain letter in the transcript never fires a buried verb, and the status bar stops enumerating verb keys (the strip is the legend). Navigation/utility keys (`j`/`k`, `g`/`G`, `m`, `?`/`h`, `q`) and graduated Esc are unchanged.
- TUI pace widget: the strip's *widget* item class. `⏎` on the held set's `pace` item enters an inline stepper (`▴ pace <v> ▾`, loud, owning the row) where `↑`/`↓` step the between-turns dial in place — each step previews by moving the live pace without pushing to the daemon, `⏎` commits the previewed speed, `Esc` reverts to the entry value (the gentlest rung of graduated Esc, nothing sent to unsend). Replaces the earlier `slower`/`faster` buttons, so between-turns pace is adjusted only here, only while held.
- TUI strip contents model: one relevance-ordered list per state, filled to the width and cut from the right, with an omnipresent dimmer tail (`pace · theme · help · detach`) that is therefore cut first — `pace` most protected, `detach` least, each with a keyboard fallback. Only verbs that apply are shown: `background`/`kill` are foreground-`bash`-only (the handoff adopts a live child; `kill` races an abort future no other backend awaits — the `interrupt` entry below since made the interruption half universal), `pace` is reachable in every state rather than only while held, and `held` is a modifier that renames the hold verb to `resume` wherever it appears. Which tool is running is read off the committed log — the last call with no paired result — so no daemon round-trip was needed. Replaces the fixed per-state-family sets and the right-pinned `detach` universal.
- `interrupt` — `POST /interrupt` now **latches** (`AtomicBool` consumed at the junctures either side of a call), so it reaches tools nothing can suspend: the loop stops and the in-flight call's output is withheld from the model, kept in the log with `wire: Elided` (its first construction site) and never sent through the redaction fork. Taken before a call runs it stops the turn instead. The strip carries it in every active state — labelled `kill` on a foreground bash, where it also kills the process group — replacing the state that offered no interruption verb at all.
- Per-session scratch dir: `serve` mints a private `$TMPDIR` (mkdtemp-style, mode 0700), exports it to every bash child (foreground and background), always grants it rw, and cleans it up on session end (`--keep-scratch` retains it). Structured tool paths expand `$TMPDIR`/`${TMPDIR}` at one choke point upstream of classify/spot/exec (frozen boot-time map, allowlist starts at exactly `{TMPDIR}`, unlisted names hard-error — never expand-to-empty); the spotter's scope block aliases `$TMPDIR` to the granted path so bash scratch writes are judgeable.

### Changed
- The session's config file is no longer named up front in the preamble — that high-salience "here's what you're allowed to do" pointer drew sessions into reading and probing their own perimeter as a first move. The perimeter stays out of attention; the gate-rejection message names the config as the request channel only when a move actually strays.
- Orientation is config, not code: the hardcoded environment block (cwd/platform/project-type, `env::orientation` + marker detection) is deleted; *where the session is* is now an ordinary `[context]` exec entry — the config-less scaffold ships `"Environment at boot" = { exec = … }`, and a written config owns the whole preamble.
- Model selection moved to a per-session `serve --model <id>` flag (default `claude-haiku-4-5` for dev).
- Tool definitions unified into one source shared by the loop, the keepalive ping, and the dev `wire` view (closing a cache-correctness gap).
- The distilled-note prefix changed from an em-dash (`— `) to the `⟢` provenance sigil already used by surfaced-context lines, so a surviving triage note is honestly signed as harness-curated output without invoking mechanism vocabulary. Render-layer only; the fork's `note` schema is unchanged.

### Fixed
- Fast-path permission grants no longer misfire on two dogfood-caught cases: a trailing fd-dup redirection (`cmd 2>&1`) stays on the bash fast path (only *file* redirections gate now), and a batched `read` spanning both `[paths]` and `[context]` grants clears per-path across the union instead of gating.
- Guard against runaway tool results overflowing the request (400 on oversized content).
- Streamed control characters, a turn-loop livelock, and a resume edge case.
- Extended thinking, end to end: the assembler folds streamed `thinking`/`redacted_thinking` blocks (signatures preserved) into leading assistant content, `project` renders them first on the wire, and the request's `thinking` field rides on `tool_choice` (main turn `auto` → adaptive+summarized; the fork's forced choice and the keepalive → disabled, the one illegal pairing made unrepresentable). Replaces the earlier thinking-disabled stopgap; thinking blocks are stored verbatim, not yet elided.
- A config edit that no longer parses fails loud, not silent: reload keeps last-good policy (fail-closed) and raises a `config-parse-error` notification naming the error, so the session learns its edit didn't take instead of thrashing. Schema-teaching headers on `efference.toml` + the config scaffold lead with the `scope`-is-a-string anti-footgun.
- Thinking is kept, not just streamed past: a committed turn's extended thinking renders as a collapsible block at the head of the turn (opening paragraphs always visible, expand for the rest, keyed by `seq` so the toggle survives re-projection) — reasoning streams too fast to read live, so the transcript holds the copy a human actually reads.
- A turn that produces no prose is visibly working: the streaming sink is typed (`Streamed` — text / thinking / tool-call-open / tool-input), so thinking and a tool call's arriving arguments reach clients as their own `/stream` events instead of not at all, and the TUI renders the live phase in full — the thinking so far, or `❯ calling <tool>…` over its JSON input as it accumulates — superseded by prose, by the next phase, and by the committed turn. The serve log prints `(generating — turn N)` before blocking on the model, so its last line is no longer a stale `idle` that reads as finished.
- Every committed grant is written to the session's config file, so that file is a complete record of the perimeter the session ran under — the artifact an operator reads and copies grants up from. `Lifetime` (`session`/`persist`) is retired: it had been drained of meaning by per-session config dirs, and every live caller hardcoded `session`, so the write-back had never run outside tests. A failed write now fails the grant rather than silently degrading it to session-only.
- A config edit is now adopted or reverted, never approved-but-inert: the session's config file is held in memory as a format-preserving TOML document under the invariant that the disk always holds the last content that parsed, so a write that doesn't parse is undone (comments and key order intact) and comes back to its author as an error naming the parse failure — the same rule for a gated tool write and an operator's hand-edit alike.
- A gate is always visible, whatever the call's length: its spotter reason, affordance, and `⏸` marker render as siblings of the exchange rather than inside its collapsible body, where a command more than a few lines long had been clipping the whole gate off screen. Structured annotations *about* a call now sit beside the exchange; the collapsible body holds only agent-generated content.
- The spotter's verdict renders beside every call it judged, stance first (`spotter cleared · …` / `watching` / `gated`), in the dim register — cleared calls included, which are most of them and previously had no surface at all, and resolved gates, where the verdict is the only record that a human overrode the spotter.
