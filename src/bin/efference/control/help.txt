$ efference control --help
Drive a running session from a script: message it, decide its gates, read it.

The agent verbs (`create`, `message`, `decide`, `interrupt`, `archive`, `status`, `transcript`) and `settle`, then the operator's route verbs (`state`, `pace`, `title`, `background`, `proposal`, `review-level`, `supervisor`, `notify`, `entries`, `image`). `efference control --help` lists them.

Usage: efference control [OPTIONS] <COMMAND>

Commands:
  create        Start an agent: a new session on this host, optionally with its first message. Answers with its id, model, working directory, where its gates go, and its status. The model is `<connection>/<model>`; omitted, it takes past picks
  message       Send an agent a message. From a session that drives it — the one that created it, its supervisor, or the operator — the message is its next user message, and an empty one continues it; from anyone else it is a note the agent may set aside. The answer says which happened
  decide        Decide the call an agent is holding for a decision. `allow` runs it, and a message rides with its result; `deny` refuses it — with a message the agent goes on under it, and a bare deny ends its turn; `escalate` leaves it held and passes it to whoever decides above you, with a message as a note to them
  interrupt     Stop what an agent is doing now. A running tool is stopped (a command with its process group) and the agent's turn ends; its next turn reads that you interrupted it. A generation in flight ends and the agent goes idle
  archive       End an agent, and the agents it created that end with it. Their logs stay on disk
  status        Where an agent stands and the call that answers it. With no agent, one line for each agent in view
  transcript    Read what an agent said and did: its messages in full, and each call on one line with what became of it. By default, what is new since your last read; `seq` reads one entry in full
  settle        Wait until an agent reaches its next decision point — a held call, a question, its turn ending, or a stop that waits on someone — and print its `/state`. Returns at once if it is already there
  state         Print a session's whole `/state` body, without waiting: where the loop is (`loop_phase`), what is in flight (`current_operations`), what each loop verb would answer now (`verbs`), the pending gate and question, the inbox, the running background processes, its usage, and its `status`
  pace          Set the operator's pace dial: how long the session waits between turns, and whether it is held at the next between-turns juncture. Transparent to the agent — the pace is never logged and never sent to the model. `hold` pauses without losing the speed underneath it; `resume` releases at that retained speed
  title         Set the session's title: the one line the session list, the TUI sidebar, and the web top bar show for it. The triage model keeps a title current on its own; this overrides it, and the next model-written title starts from what you set. The session's id (its address) never changes
  background    Detach the tool the session is running into the background process monitor: it keeps running as a `p#<n>` process and stops blocking the turn. The alternative to `interrupt` for a command that should finish but should not be waited on. No-op when nothing is mid-tool, and it lands only while the call is still running
  proposal      Resolve a pending config-edit proposal — the spotter's prefix-promotion, filed non-blocking and inert until an orchestrator-above decides it. Ids and the proposed change come from `state.proposals`. With no `cancel`, the proposal commits: its change folds into the effective config, and for a session-visible key (`scope`, `paths`) the session is notified. `cancel` drops it from the queue instead, audit-only, touching nothing
  review-level  Set who reviews a tool call the permission fast path did not clear
  supervisor    Set which session supervises a session, or clear it. A session's supervisor answers its gates when its review level is `supervisor` (a session at `spotter_human` moves there when given one), drives it with `message`, `decide`, and `interrupt`, and is woken by its status. By default it is the session that created it; a session the operator created has none. Clearing hands its gates to the operator, and a gate already held is re-routed rather than dropped
  notify        File an ambient message in a session's inbox under a label of your choosing. It does not interrupt: it waits for the session's next triage point and is delivered there — a build result, a review comment, a change upstream. The operator's verb for scripts; an agent's note is `message` from a session that does not drive its target
  entries       Fetch whole log entries by `seq` — the full record behind a `transcript` line: a result's complete body, a call's exact arguments, a verdict's every field. Each entry can be large; ask for the ones you need, not a range. An image on a result is referenced, not inlined; `image` fetches its bytes
  image         Fetch an image the session actually saw: the bytes stored on a logged tool result, not a re-read of the file they came from, which may since have changed. `seq` is the log entry whose result carried the image. Over MCP the image comes back as an image content block; at a terminal it is written to a file
  help          Print this message or the help of the given subcommand(s)

Options:
      --bind <ADDR:PORT>
          Listen on a TCP address as well: the web client's front door. A port (`8080`), an address (`127.0.0.1:8000`, `0` for one the kernel picks), or `host:port`; a bare port means loopback, and a cleartext bind is accepted only there, so the short spelling never widens exposure. With `--host`, overrides `[host] bind`; `--bind ""` serves the Unix socket alone whatever the table says.
          
          Without `--host` this is the standalone host's: with no host running, a standalone host answers in the browser on that address instead of in the TUI.

      --host-socket <PATH>
          The host's control socket every verb addresses; a named session resolves through it. Defaults to the first live of `.efference/host.sock` here and `~/.efference/host.sock`, else the latter

  -h, --help
          Print help (see a summary with '-h')

$ efference control image -h
Fetch an image the session actually saw: the bytes stored on a logged tool result, not a re-read of the file they came from, which may since have changed. `seq` is the log entry whose result carried the image. Over MCP the image comes back as an image content block; at a terminal it is written to a file

Usage: efference control image [OPTIONS] <SEQ> [IDX]

Arguments:
  <SEQ>  The `seq` of the log entry whose result carried the image
  [IDX]  Which image on that result, when it carried several [default: 0]

Options:
      --bind <ADDR:PORT>    Listen on a TCP address as well: the web client's front door. A port (`8080`), an address (`127.0.0.1:8000`, `0` for one the kernel picks), or `host:port`; a bare port means loopback, and a cleartext bind is accepted only there, so the short spelling never widens exposure. With `--host`, overrides `[host] bind`; `--bind ""` serves the Unix socket alone whatever the table says
      --host-socket <PATH>  The host's control socket every verb addresses; a named session resolves through it. Defaults to the first live of `.efference/host.sock` here and `~/.efference/host.sock`, else the latter
  -o, --out <OUT>           Where to write the bytes. Command-line only; over MCP the image is returned inline and nothing is written. Defaults to `image-<seq>-<idx>.<ext>` in the current directory
      --agent <AGENT>       The agent's id. Defaults to the one session live here
  -h, --help                Print help (see more with '--help')
